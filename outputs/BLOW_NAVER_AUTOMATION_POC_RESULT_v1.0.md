# BLOW 네이버 자동 입력 POC 최종 결과 v1.0

- 판정일: 2026-09-09
- 판정: 조건부 진행
- 검증 브랜치: `feat/naver-connection-poc`
- 검증 환경: Windows 10 10.0.19045, Chrome 152.0.7977.76

## 1. 최종 판단

네이버 블로그 편집기에서 제목, 본문, 이미지, 구분선, 스티커, 인용구를 입력하고 임시저장까지 수행하는 핵심 자동화의 기술적 가능성을 확인했다. 로그인 만료, 네트워크 단절, 화면 구조 변경과 사용자 개입이 발생했을 때 남은 작업을 멈추는 안전 동작도 확인했다.

따라서 BLOW는 MVP 개발로 조건부 진행할 수 있다. 다만 현재 결과는 기술검증이며 배포 가능한 완성 제품을 의미하지 않는다. 네이버 정책 검토, 실제 사용자 환경 검증, 계정·이용권·API 키 보안과 업데이트 체계는 MVP 단계에서 별도로 구현해야 한다.

## 3. 의도적으로 제외한 기능

- 최종 발행: BLOW가 누르거나 자동화하지 않는다.
- 글꼴, 글 정렬, 글자 크기: 네이버 블로그의 사용자 기본 설정을 따른다.
- 네이버 아이디와 비밀번호 저장: 전용 Chrome에서 사용자가 직접 로그인하며 BLOW는 로그인 정보를 읽거나 저장하지 않는다.
- 빠른 Chrome 10회 재실행: 로그인 보호 절차를 유발할 수 있어 자동 검증에서 제외한다.
- Chrome 직전 정식 버전: 정식 출시 또는 초기 고객 확대 전에 후속 검증한다.

## 4. 출시 전 후속 확인

1. 자연스러운 사용 간격으로 전용 Chrome 수동 재실행 1–3회
2. 네이버 약관과 자동화 정책 검토
3. Windows 설치 파일과 코드 서명 준비
4. 네이버·Chrome 변경에 대응하는 업데이트와 오류 수집 체계
5. API 키 로컬 암호화, 앱 제거와 탈퇴 시 완전 삭제 검증
6. 개발 전용 계정이 아닌 별도 내부 테스트 계정으로 제한된 베타 검증

## 5. 남은 위험

- 네이버 화면 구조가 바뀌면 선택자 조정과 재검증이 필요하다.
- 네이버가 추가 인증이나 로그인 보호 절차를 표시하면 자동화는 멈추며 사용자가 직접 인증해야 한다.
- 사용자 PC의 보안 프로그램, Chrome 확장 기능과 운영체제 설정에 따라 동작이 달라질 수 있다.
- 현재는 Windows 10과 최신 정식 Chrome 한 조합에서 검증했으므로 지원 환경 확대 전 추가 검증이 필요하다.

## 6. 다음 개발 단계

다음 단계는 POC 기능을 더 늘리는 것이 아니라 MVP 범위를 확정하는 것이다. 계정, 이용권, 기기 제한, 로컬 프로젝트 저장, OpenAI API 키 보안, 글 생성과 관리자 기능을 별도 설계한 뒤 POC에서 검증된 네이버 어댑터를 재사용한다.
