# BLOW MVP 결정 005 — 개인정보·약관·환불 검토

> 확인일: 2026-09-09
> 상태: 사용자 승인 완료
> 확정안: 내부 사실 정리·초안 작성 후 국내 전문 변호사의 출시 전 최종 검토
> 적용 시점: 네이버의 서면 허락을 받은 뒤, 첫 유료 판매 전에 완료

## 1. 결정 대상

BLOW의 개인정보처리방침, 이용약관, 환불 기준과 판매 고지를 누가 어떤 범위까지 검토할지 정한다.

이 문서는 법률 자문이나 최종 약관이 아니다. 현재 제품 구조를 기준으로 필요한 검토 범위와 완료 조건을 정하는 개발·운영 결정서다.

## 2. 확정 담당 방식

다음과 같이 역할을 나눈다.

1. 제품 운영자: 실제 사업자 정보, 판매 방식, 수집 데이터, 보관 기간과 외부 서비스 목록을 확정한다.
2. 개발 담당: 코드·데이터베이스·로그가 확정된 사실과 일치하는지 확인하고 초안을 작성한다.
3. 국내 전문 변호사: 개인정보, 전자상거래, 디지털 콘텐츠와 소프트웨어 이용계약 관점에서 최종 검토한다.
4. 세무·행정 담당: 사업자등록, 부가가치세와 통신판매업 신고 필요 여부를 별도로 확인한다.

자체 작성만으로 출시하거나 범용 약관 템플릿의 상호만 바꾸는 방식은 사용하지 않는다. 외부 전문가는 개인정보와 온라인 소프트웨어 판매 경험이 있는 국내 변호사 또는 법무법인을 대상으로 2~3곳의 범위와 견적을 비교한 뒤 선정한다.

## 3. 검토가 필요한 이유

- 개인정보 보호법은 처리 목적, 항목, 보유 기간, 파기, 위탁, 이용자 권리와 보호책임자 연락처 등을 처리방침에 공개하도록 요구한다.
- Supabase와 Amazon SES를 서울 리전으로 사용해도 공급자의 지원, 하위 처리자와 이메일 전달 과정까지 포함한 실제 처리 위치를 확인해야 한다.
- 사용자가 자신의 OpenAI API 키로 글을 생성하더라도 입력 내용이 OpenAI로 전송되는 사실과 법적 역할을 명확히 설명해야 한다.
- 수동 계좌이체를 사용해도 온라인으로 이용권을 판매하면 전자상거래·통신판매 규정이 적용될 가능성이 있으므로 신고와 판매 고지를 확인해야 한다.
- 디지털 콘텐츠의 청약철회를 제한하려면 제한 사실을 명확하게 알리고 시험 사용 또는 이에 준하는 정보를 제공하는 등 법정 요건을 검토해야 한다.
- “사용 후 환불 불가”나 과도한 책임 면제 문구는 약관에 적었다는 이유만으로 유효해지지 않는다.
- 사용자 동의는 네이버가 금지한 자동화를 허용하는 수단이 아니므로 네이버 서면 허락이 별도로 필요하다.

## 4. 검토 문서와 화면

### 4.1 개인정보

- 개인정보처리방침
- 개인정보 수집·이용의 법적 근거와 필요한 동의 화면
- Supabase, Amazon SES와 향후 고객지원 도구의 위탁·국외 이전 표시
- 개인정보 열람, 정정, 삭제, 처리정지와 탈퇴 절차
- 개인정보 유출 대응 및 문의 창구
- 로컬 PC에만 저장되는 콘텐츠와 삭제 주기 안내

개인정보처리방침은 공개 문서이고 모든 처리를 반드시 동의에만 의존하는 문서는 아니다. 기존 PRD의 “개인정보처리방침 필수 동의”를 그대로 구현하지 않고, 계약 이행 등 처리 근거와 별도 동의가 필요한 항목을 전문가가 구분한 뒤 확인·동의 UI를 확정한다.

### 4.2 이용계약

- BLOW 이용약관
- 한 계정·한 PC·한 블로그 제한
- 이용권 시작, 연장, 만료와 정지 기준
- 지원 환경, 장애, 업데이트와 서비스 종료 절차
- 사용자 콘텐츠와 생성 결과의 책임 범위
- OpenAI API 별도 비용과 사용자 소유 키 사용 안내
- 네이버와 제휴 관계가 아니라는 사실 및 허용 범위 안내
- 금지 행위, 계정 정지, 계약 해지와 이의 신청 절차

### 4.3 판매와 환불

- 판매 페이지의 사업자 정보, 가격 39,000원, 이용 기간 30일과 제공 내용
- 수동 입금 확인, 이용 시작 시점과 현금영수증·세금 처리
- 청약철회, 중도 해지, 서비스 장애와 중복 입금 환불 기준
- 이용 시작 전 전액 환불과 이용 시작 후 일할 계산안의 적법성
- 환불 신청 경로, 처리 기한과 지급 방법
- 통신판매업 신고 및 디지털 콘텐츠 관련 고지 필요 여부

정확한 환불 산식과 공제 항목은 법률 검토 전 코드와 약관에 고정하지 않는다.

### 4.4 동의와 증거

- 적용 문서의 종류, 버전, 동의 또는 확인 시각을 기록한다.
- 약관과 개인정보 관련 화면을 구분한다.
- 구매 전에 이용 기간, 핵심 제한, 환불 기준과 별도 OpenAI 비용을 확인할 수 있게 한다.
- 중요한 변경은 변경 내용을 알리고 필요한 경우 재동의받는다.
- 이전 버전 문서를 보관하고 사용자가 현재 문서를 언제든 다시 열 수 있게 한다.

## 5. BLOW의 현재 데이터 사실

### 서버 저장 예정

- 회원 이메일과 인증 상태
- 이용권 상태와 시작·종료일
- 등록 기기의 비가역 해시와 등록 블로그 식별값
- 입금·이용권 관리 기록
- 약관 관련 문서 버전과 확인 시각
- 관리자 감사 기록과 최소 보안 접속 기록

### 서버 저장 금지

- 네이버 아이디, 비밀번호와 로그인 세션
- OpenAI API 키
- 브랜드 프로필, 주제, 키워드, 제목과 본문
- 참고자료, 첨부 이미지와 생성 이미지

### 사용자 PC 처리

- OpenAI API 키는 Windows 보안 저장소에 보관한다.
- 글, 참고자료와 이미지는 정해진 기간 동안 로컬에만 보관한 뒤 삭제한다.
- 네이버 로그인은 전용 Chrome에서 사용자가 직접 수행한다.
- 행동 분석, 클릭 추적과 화면 체류시간은 수집하지 않는다.

법률 문서와 실제 코드가 다르면 코드 또는 문서를 수정한 후 출시한다.

## 6. 거래기록과 탈퇴 데이터

현재 전자상거래법 시행령은 표시·광고 기록 6개월, 계약·청약철회 기록 5년, 결제·공급 기록 5년, 소비자 불만·분쟁 기록 3년을 정하고 있다.

따라서 회원 탈퇴 시 일반 계정 데이터는 삭제하되 법령상 보존이 필요한 거래 기록은 목적별로 분리하고 접근을 제한해야 한다. BLOW에 실제로 적용되는 기록 종류와 기간은 판매 구조가 확정된 뒤 전문가가 다시 확인한다.

## 7. 전문가에게 확인할 핵심 질문

1. BLOW 30일 이용권이 디지털 콘텐츠, 용역 또는 다른 계약 유형 중 어디에 해당하는가?
2. 수동 계좌이체 판매에 필요한 통신판매업 신고와 사전 고지는 무엇인가?
3. 이용 시작 전 전액 환불과 시작 후 일할 계산이 법정 청약철회와 충돌하지 않는가?
4. 무료 체험이 없는 경우 구매 전 어떤 시험 사용 또는 상세 정보를 제공해야 하는가?
5. Supabase, Amazon SES와 OpenAI 관련 위탁·국외 이전을 어떤 법적 근거와 문구로 공개해야 하는가?
6. 등록 기기 해시와 블로그 식별값의 정확한 보유 기간은 얼마인가?
7. 개인정보처리방침 확인과 별도 수집·이용 동의를 어떻게 구분해야 하는가?
8. 회원 연령 제한 또는 법정대리인 절차가 필요한가?
9. 네이버의 서면 허락 내용과 서비스 중단 위험을 이용약관에 어떻게 반영해야 하는가?
10. 사업자 정보, 고객지원 연락처, 현금영수증과 세금 관련 표시가 충분한가?

## 8. 진행 시점

### 지금 수행

- 제품 데이터 흐름과 저장·삭제 사실을 문서로 유지한다.
- 법률 검토 질문과 필요한 증빙을 준비한다.
- 환불 산식과 동의 화면을 아직 코드로 확정하지 않는다.

### 네이버 서면 허락 후 수행

1. 사업자명, 대표자, 주소, 연락처, 도메인과 판매 주체를 확정한다.
2. Supabase, Amazon SES와 OpenAI의 계약·개인정보 자료를 다시 확인한다.
3. 실제 구현과 일치하는 세 문서 초안을 작성한다.
4. 국내 전문 변호사 2~3곳에서 범위와 비용 견적을 받는다.
5. 사용자가 업체와 비용을 승인한 뒤 최종 검토를 의뢰한다.
6. 수정된 문서와 환불 계산을 코드·판매 화면에 반영한다.
7. 첫 유료 사용자 결제 전에 최종본을 공개한다.

## 9. 완료 기준

- LEG-01: 실제 사업자와 고객지원 정보가 모든 판매 화면과 문서에서 일치한다.
- LEG-02: 수집·로컬 처리·서버 저장·외부 전송 데이터가 실제 코드와 일치한다.
- LEG-03: 위탁, 국외 이전, 보유 기간과 파기 방법이 공급자별로 확인된다.
- LEG-04: 이용약관, 개인정보처리방침과 환불 규정의 목적과 동의 방식이 구분된다.
- LEG-05: 이용 시작 시점, 청약철회와 중도 환불 산식이 명확하다.
- LEG-06: 법정 거래기록은 탈퇴 회원 데이터와 분리해 필요한 기간만 보관한다.
- LEG-07: 네이버 허용 범위와 서비스 중단 가능성을 고지하되 사업자의 법적 책임을 부당하게 면제하지 않는다.
- LEG-08: 사용자가 구매 전에 가격, 기간, 기능 제한, 환불과 OpenAI 별도 비용을 확인한다.
- LEG-09: 국내 전문 변호사의 수정 의견이 문서와 제품에 모두 반영된다.
- LEG-10: 검토 후 변경된 코드와 화면을 다시 대조하고 최종 승인 기록을 남긴다.

## 10. 비용과 승인 기준

- 법률 검토는 유료 외부 작업이며 비용은 업체와 범위에 따라 달라진다.
- 견적을 받기 전 사업자 정보와 제품 구조를 확정해 불필요한 재검토 비용을 줄인다.
- 외부 업체에 문서를 보내기 전에 비밀정보와 실제 사용자 데이터를 제거한다.
- 계약, 결제와 개인정보 제공은 사용자가 업체·범위·금액을 확인하고 승인한 뒤 진행한다.

## 11. 아직 실행하지 않는 작업

- 변호사 또는 법무법인 선정·문의·계약·결제
- 최종 개인정보처리방침과 이용약관 작성
- 환불 산식 확정과 자동 계산 구현
- 사업자등록 또는 통신판매업 신고
- 운영 사업자 정보와 개인 연락처 공개

네이버의 서면 허락과 판매 주체 확정 전에는 외부 법률 비용을 지출하지 않는다.
