# BLOW 0.1.5 — 저장 확인·작업 내역·본문 배치 개선

## 변경 내용

1. **저장 판정 수정**: 저장 버튼 클릭만 성공해도 완료로 반환하던 코드를 수정했습니다. 최대 10초 동안 새로운 완료 안내, 임시저장 개수 증가, 저장 시각 변경 또는 명시적인 완료 상태를 확인합니다. HTTP 200 응답이나 버튼 활성화 복귀만으로는 성공 처리하지 않습니다. 불확실한 경우 자동 재클릭·최종 발행 없이 멈춥니다. 탐색 중 사라진 광고 프레임은 건너뜁니다.
2. **작업 내역 누락 방지·복구**: 네이버 저장 후 작성 목록 체크포인트 저장에 실패해도 작업 내역 기록은 시도합니다. 기록만 실패한 경우 ‘작업 내역 다시 기록’을 표시하며, 다시 시작한 앱에서도 복구할 수 있습니다. 같은 작업 ID의 내역을 중복 생성하지 않습니다. 기록 재시도는 AI·네이버 저장을 실행하지 않습니다.
3. **이미지 중간 배치**: 본문 분량과 기존 내용 전환 지점 계산을 이용해 이미지들을 본문 중간에 분산합니다. 원문 문단을 확인하고 커서를 옮긴 뒤 첨부하며, 지정한 두 문단 사이에 실제로 들어갔는지도 검사합니다. 끝에 몰아넣는 대체 처리는 하지 않습니다.
4. **모바일 문단 나누기**: 문장 경계를 기준으로 대체로 1–2문장씩 묶고, 긴 문장은 기존 공백에서 나눕니다. 단어·숫자·URL·지정 키워드를 훼손하지 않으며, 추가 AI 호출을 하지 않습니다. 편집기에는 실제 Enter 입력으로 빈 문단을 넣습니다.
5. **오류 위치 표시**: 실패한 경우 글 생성·이미지 배치·꾸미기·임시저장 중 어느 단계였는지 작성 목록에 남깁니다. 기존 재생성·설정 불러오기·삭제 후 입력 복구 기능은 유지합니다.

사용자의 마지막 상태 화면이 없어 이번 실제 실패의 단일 원인은 확정하지 않았습니다. 위 저장 판정과 기록 경로의 코드상 결함을 수정했으며, 실제 네이버 환경에서의 최종 검증은 남아 있습니다. 과거 누락된 내역이나 저장 여부가 불확실한 글은 임의로 복구·재저장하지 않았습니다.

## 주요 수정·생성 파일

- `packages/naver-adapter/src/naver-draft-save.ts`: 완료 신호 확인, 오판 방지.
- `packages/naver-adapter/src/naver-editor.ts`: 실제 문단 입력 및 이미지 기준 문단 확인.
- `packages/naver-adapter/src/naver-image.ts`: 이미지 분산 삽입과 위치 검증.
- `packages/naver-adapter/src/naver-connection.ts`, `apps/desktop/src/main/naver-connection.ts`: 문단 위치 전달.
- `apps/desktop/src/main/index.ts`, `src/preload/index.ts`, `src/preload/global.d.ts`: 이미지 위치 입력 검증·앱 내부 전달.
- `apps/desktop/src/main/work-history.ts`: 작업 ID 기준 기록 중복 방지.
- `apps/desktop/src/renderer/mobile-post-layout.ts` (신규): 로컬 문단 정리·이미지 위치 계산.
- `apps/desktop/src/renderer/post-decoration.ts`: 기존 내용 전환 위치 계산 재사용.
- `apps/desktop/src/renderer/automatic-writing.ts`, `writing-queue.ts`, `useWritingQueue.ts`: 저장 후 기록 복구와 상태 보관.
- `apps/desktop/src/renderer/WritingQueuePanel.tsx`, `NewPostScreen.tsx`: 기록 재시도 버튼·중복 동작 방지.
- 각 관련 단위 테스트 및 `apps/desktop/scripts/check-post-layout.ts` (신규), `check-writing-recovery.mjs`.
- `apps/desktop/package.json`, `package-lock.json`: 데스크톱 테스트 버전 0.1.5.

ponytail 원칙에 따라 기존 계산·저장 구조를 재사용했으며 신규 의존성·DB 변경은 없습니다. UI 복구 원칙에 따라 실패 이유 옆에 복구 버튼을 제공하고, 처리 중 중복 클릭과 입력을 차단하되 실패 후 다시 조작할 수 있도록 검증했습니다.

## 검증 결과

- 워크스페이스 전체 TypeScript 검사 통과.
- 단위 테스트 **31개 파일, 379개 통과**.
- Chrome 복구 UI 검사 **9개**, Windows Electron 격리 환경 **9개** 통과.
- 기존 자동 작성 UI 회귀 검사 **11개** 통과.
- 별도 편집기 통합 검사 **4개** 통과: 실제 키보드 문단 입력·이미지 3장 중간 배치·원문 보존, 2.1초 지연 후 저장 완료, 오래된 완료 표시/클릭만으로 성공하지 않음, 끝에 잘못 첨부된 이미지 탐지.
- 375px 화면에서 본문 넘침 없음, 이미지 사이에 텍스트 문단 유지. 테스트용 화면 캡처 시각 검수 완료.
- 설치파일 압축 무결성 검사 통과. 패키지 버전·메인·프리로드·렌더러·네이버 어댑터가 최종 빌드 결과와 동일함을 확인.
- `.env`, Chrome 프로필, `.local`, `Secure` 파일/경로가 패키지에 포함되지 않음을 확인.

테스트는 가짜 응답과 개발용 편집기, 별도 프로필로 수행했습니다. 실제 계정 데이터 변경, 유료 AI 호출, 네이버 글 입력·임시저장·발행은 하지 않았습니다.

## 설치 및 확인 순서

1. BLOW와 BLOW 전용 Chrome을 닫습니다.
2. `apps/desktop/release/BLOW-Setup-0.1.5-x64.exe`를 실행해 업데이트합니다. **기존 앱을 먼저 제거하지 마세요.** 제거 과정에서 로컬 설정·로그인 정보가 삭제될 수 있습니다.
3. 블로그 연결을 확인하고, 기존에 저장된 글이 있는지 네이버 임시저장 목록부터 확인합니다. 불확실한 기존 항목을 재생성하면 중복 글과 새 API 비용이 발생할 수 있습니다.
4. 테스트 글 하나를 실행한 뒤 BLOW 작업 내역과 네이버 임시저장 목록 양쪽을 확인합니다. 글·이미지 생성에는 기존과 동일하게 API 사용료가 발생합니다.
5. 네이버에 저장된 글에서 이미지가 본문 중간에 있는지, 문단이 짧게 나뉘었는지 확인합니다. 최종 발행은 사용자가 합니다.
6. ‘작업 내역 다시 기록’이 보이면 해당 버튼으로 기록만 복구할 수 있습니다. AI 비용과 네이버 재저장은 없습니다.
7. 멈출 경우 작성 목록의 ‘중단 단계’와 오류 문구를 캡처해 주세요. 자동으로 같은 글을 반복 실행하지 않습니다.

이 파일은 내부 테스트용 미서명 설치파일입니다. Windows 보안 경고가 나타날 수 있으며, 코드 서명·공개 배포는 하지 않았습니다.
