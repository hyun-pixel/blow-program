# BLOW UI·UX 재설계 방향 v2.0

> 상태: 시각 방향 검토안
> 범위: 사용자 앱의 홈, 새 글 작성, 작업 진행 화면
> 원칙: 기능과 정보 구조는 유지하고 시각 언어를 다시 설계한다.

## 1. 디자인 해석

BLOW는 브랜드 블로그 담당자가 매일 반복해서 사용하는 Windows 기반 편집 도구다. 첫인상을 위한 홍보 화면보다 입력 속도, 상태 확인, 실수 방지가 중요하다.

- 디자인 유형: 업무용 데스크톱 앱
- 사용자: 미용실, 법률, 보험, 뷰티 업종의 비개발자 실무자
- 시각 언어: 차분한 편집 도구, 익숙한 업무 소프트웨어, 높은 정보 밀도
- 디자인 변화량: 3 / 10
- 움직임 강도: 2 / 10
- 정보 밀도: 7 / 10
- 재설계 방식: 화면 구조는 보존하고 표현 방식은 전면 교체

## 2. 현재 시안이 AI처럼 보이는 이유

1. 영문 대문자 소제목이 거의 모든 영역에 반복된다.
2. `01`, `02`, `NEW POST`, `IN PROGRESS`, `SUMMARY` 같은 장식용 라벨이 많다.
3. 모든 정보를 둥근 카드에 넣어 각 영역이 서로 경쟁한다.
4. 상태마다 배지와 색상 배경을 사용해 실제 중요도보다 화면이 화려하다.
5. 아이콘이 색상 상자 안에 반복되어 AI 서비스 소개 화면처럼 보인다.
6. 홈 화면이 작업 도구보다 SaaS 홍보용 대시보드처럼 구성되어 있다.
7. 설명 문장이 기능 이름보다 앞서 사용자의 읽기 부담이 크다.
8. 파란색 면적이 넓어 브랜드 색상이 행동 구분이 아닌 장식으로 소비된다.

## 3. 새로운 디자인 원칙

### 3.1 작업 화면이 중심이다

- 홈에서 큰 환영 영역을 제거한다.
- 첫 화면 상단에는 `작업` 제목과 `새 글 작성` 버튼만 둔다.
- 최근 작업과 연결 상태를 표와 제목-값 행으로 보여준다.
- 사용자가 앱을 열고 3초 안에 다음 행동을 찾을 수 있어야 한다.

### 3.2 카드는 필요한 곳에만 사용한다

- 일반 정보 묶음은 흰색 카드가 아니라 간격과 구분선으로 나눈다.
- 테두리가 있는 면은 편집 영역, 팝오버, 대화상자처럼 경계가 필요한 곳에만 사용한다.
- 카드 안에 카드를 넣지 않는다.
- 그림자는 메뉴, 팝오버, 대화상자에만 사용한다.

### 3.3 색은 행동과 상태에만 사용한다

- 파란색은 주요 버튼, 현재 메뉴, 선택 상태에만 사용한다.
- 넓은 파란 배경과 장식용 그라데이션을 제거한다.
- 성공, 주의, 오류 색은 실제 상태가 발생한 순간에만 표시한다.
- 대기 상태는 회색 문구와 선형 아이콘으로 표현한다.

### 3.4 장식용 문구를 제거한다

- 영문 대문자 소제목을 사용하지 않는다.
- 섹션 번호를 사용하지 않는다.
- `현재 작업`, `모델`, `이미지`, `글 설정`처럼 사용자가 바로 이해하는 한국어를 쓴다.
- 같은 안전 문구를 여러 화면에서 반복하지 않는다.

### 3.5 편집 도구처럼 보이게 한다

- 왼쪽은 내비게이션, 가운데는 작업 문서, 오른쪽은 속성 설정으로 구분한다.
- 오른쪽 설정 영역은 카드 모음이 아니라 하나의 연속된 검사기 패널로 만든다.
- 하단에는 현재 설정 요약과 단일 주요 버튼을 둔다.
- 문서 편집기, 디자인 도구, 업무용 작성 프로그램에서 익숙한 배치를 따른다.

## 4. 시각 체계

### 색상

- 앱 바탕: `#F4F5F7`
- 작업 영역: `#FFFFFF`
- 기본 글자: `#171A1F`
- 보조 글자: `#626A76`
- 구분선: `#D9DDE3`
- 조작 요소 경계: `#8A929E`
- 주요 행동: 기존 BLOW 파란색 `#1E40AF`
- 선택 배경: 파란색을 매우 옅게 사용하되 넓은 면에는 적용하지 않는다.

### 형태

- 입력과 버튼 모서리: 6px
- 패널 모서리: 사용하지 않거나 4px 이하
- 대화상자 모서리: 8px
- 알약 모양 배지: 사용하지 않음
- 아이콘 배경 상자: 사용하지 않음
- 기본 구분 방식: 1px 선과 여백

### 타이포그래피

- 기본 글꼴: SUIT Variable 유지
- 화면 제목: 22px, 700
- 영역 제목: 16px, 600
- 본문과 입력값: 14px, 400 또는 500
- 보조 설명: 13px, 400
- 숫자와 날짜: 고정폭 숫자 사용
- 화면당 제목 계층은 세 단계 이내로 제한
- 한 문단의 설명은 두 줄을 넘기지 않음

### 아이콘

- 한 종류의 선형 아이콘만 사용한다.
- Fluent UI를 실제 구성 요소 기반으로 채택하면 Fluent System Icons로 함께 통일한다.
- 아이콘은 기능 식별이 빨라지는 경우에만 사용한다.
- 제목과 설명 옆의 장식용 아이콘은 제거한다.

### 움직임

- 화면 입장 애니메이션을 제거한다.
- 버튼, 메뉴, 패널 열림에만 120-160ms 전환을 사용한다.
- 진행 중 표시는 텍스트 상태 변화와 제한적인 로딩 표시만 사용한다.
- 위치 이동, 확대, 반짝임, 반복 펄스를 사용하지 않는다.

## 5. 화면별 재구성

### 5.1 홈

상단에는 `작업` 제목, 이용 종료일, `새 글 작성` 버튼을 한 줄로 배치한다.

연결 상태는 카드 네 개가 아니라 한 줄 상태 영역으로 만든다.

```text
네이버 연결됨    OpenAI 준비됨    브랜드 프로필 완료    이용 종료 2026.10.02
```

최근 작업은 일반적인 업무 목록으로 표시한다.

```text
제목                         상태           수정 시간
가을 웨딩 헤어 추천          임시저장 완료   오늘 14:22
손상모 관리 방법             임시저장 완료   어제 17:08
두피 케어가 필요한 신호      작업 중단       8월 31일
```

월간 작업 수는 독립 카드로 강조하지 않고 목록 상단의 보조 정보로 표시한다.

### 5.2 새 글 작성

중앙 작업 영역과 오른쪽 설정 패널의 두 열을 유지한다.

중앙 영역은 다음 순서의 연속된 양식으로 구성한다.

```text
글 내용
주제
키워드
글 유형과 분량
참고자료
CTA
```

각 영역은 번호 대신 제목과 한 줄 구분선으로 나눈다. 설명은 처음 사용하는 사람에게 필요한 경우에만 표시한다.

오른쪽 설정 패널은 하나의 연속된 속성 영역으로 구성한다.

```text
작성 설정
모델
추론 강도
가독성 기준
이미지 생성과 첨부
스티커, 인용구, 구분선
강조색
```

모델 설명과 이미지 옵션은 선택했을 때만 세부 항목을 펼친다. 화면 하단 작업 막대에는 조건 요약과 `글 생성` 버튼만 둔다.

### 5.3 작업 진행

큰 색상 강조 영역을 제거하고 설치 프로그램이나 파일 처리 도구처럼 구성한다.

```text
글 작성 중                                      경과 02:18
현재 작업: 이미지 생성 2 / 4

완료  입력 검사
완료  참고자료 분석
완료  본문 생성
완료  글자와 키워드 검사
진행  이미지 생성
대기  네이버 입력
대기  임시저장 확인
```

현재 단계만 왼쪽에 파란색 2px 표시선을 둔다. 완료 상태는 작은 체크 아이콘과 일반 글자로 표현한다. 오른쪽 작업 요약은 카드가 아니라 세로 제목-값 목록으로 표시한다.

`이미지만 취소`는 보조 버튼, `전체 작업 중단`은 텍스트형 위험 행동으로 분리한다.

## 6. 유지할 요소

- 왼쪽 내비게이션 구조
- 한 화면에 많은 정보를 보여주는 작성 화면
- 65:35 작성 화면 비율
- SUIT 글꼴
- BLOW 파란색 주요 행동
- 44px 조작 영역
- 명확한 오류와 중단 상태
- 사용자가 직접 발행하는 흐름

## 7. 제거할 요소

- 홈의 파란 환영 배너
- 모든 영문 대문자 소제목
- 작성 화면의 `01-04` 번호
- 반복되는 둥근 카드
- 장식용 상태 배지
- 색상 상자 안의 아이콘
- 화면 입장 애니메이션
- 같은 의미의 도움말 반복
- 실제 데이터처럼 보이는 과도하게 꾸민 예시 수치

## 8. 구현 기반 추천

실제 앱은 React 기반에서 Fluent UI v9를 접근성과 상호작용 기반으로 사용하고, 기본 테마를 그대로 노출하지 않고 BLOW의 색상, 간격, 타이포그래피 토큰을 적용하는 방향을 추천한다.

- 구성 요소: Fluent UI v9
- 아이콘: Fluent System Icons
- 글꼴: 앱에 포함한 SUIT Variable
- 화면 구조: CSS Grid
- 상태 관리: 작성 화면 단위 로컬 상태와 작업 전역 상태 분리
- 애니메이션 라이브러리: MVP에서는 추가하지 않음

## 9. 다음 시안의 합격 기준

1. 카드가 없어도 정보 묶음이 명확해야 한다.
2. 화면에서 영문 장식 라벨과 섹션 번호가 보이지 않아야 한다.
3. 주요 파란색 버튼은 화면당 하나만 보여야 한다.
4. 홈 화면이 홍보 페이지가 아니라 작업 목록처럼 보여야 한다.
5. 작성 화면이 대시보드보다 문서 편집 도구처럼 보여야 한다.
6. 모든 텍스트를 읽지 않아도 작업 순서를 이해할 수 있어야 한다.
7. 1366 × 768에서 주요 입력과 생성 버튼을 찾기 쉬워야 한다.
8. Windows 배율 150%에서도 정보가 잘리거나 겹치지 않아야 한다.
