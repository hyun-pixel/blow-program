# BLOW 사용자 앱 UI·UX 개편 v3.2

작성일: 2026-09-24

현재 기준: 밝고 차분한 세로형 작성 화면. 네이버 연결 → 글별 설정 → 실행 전 확인 → 자동 작성·검사·임시저장 → 사용자 최종 검토 순서다. 아래 날짜별 기록은 누적 변경 이력이며 최신 항목을 우선한다.

## 이번 요청과 승인 범위

1. ‘시작하기’ 메뉴를 제거하고 ‘블로그 세팅’을 기본 화면으로 사용한다.
2. 작성 항목을 세로 한 열로 배치한다. 각 영역에 번호·제목·설명과 충분한 간격을 둔다.
3. ‘브랜드 정보’의 화면 명칭을 ‘블로그 세팅’으로 변경하고, 그 안에 AI 연결과 네이버 연결 설정을 둔다.
4. 왼쪽 대분류 없이 블로그 세팅 → 새 글 작성 → 작업 내역 → 사용 가이드 순으로 배치한다.
5. 추가 확인을 통해 사용자가 인용구·스티커·구분선을 글 생성 전에 선택하도록 필요한 기능 수정을 승인했다.

## 작성 화면

총 11개 영역을 위에서 아래로 표시한다.

1. 글 주제
2. 글 유형
3. 글 길이
4. 키워드와 반복 횟수
5. 상품·서비스
6. 마지막 안내 문구
7. AI 모델과 검토 깊이
8. AI 이미지 사용 여부·장수·비율·품질·스타일
9. 인용구
10. 스티커
11. 구분선

기존 필수 입력, 기본값, 키워드 검증, 비용 고지, 생성 취소와 결과 확인을 유지한다. 모델 상세 설명만 선택적으로 펼쳐 볼 수 있다. 사용하지 않는 이미지·꾸미기의 하위 설정은 사용을 선택할 때 나타난다.

## 꾸미기 사전 설정

- 기본값은 세 항목 모두 ‘사용 안 함’이다.
- 각 항목은 첫 번째/마지막 문단, 문단 앞/뒤 위치를 선택할 수 있다.
- 인용구·구분선은 기존 네이버 어댑터가 지원하는 디자인 번호 또는 무작위를 선택한다.
- 스티커는 계정별 묶음이 달라, 실제 목록 중 무작위 묶음 또는 연결 후 직접 선택을 지정한다.
- 설정은 생성된 글과 함께 네이버 화면으로 전달한다. AI 글 생성 요청에는 추가하지 않는다.
- 네이버 목록 조회 후 사전 선택한 디자인이 없으면 임의로 대체하지 않고 재선택을 요구한다.
- 사진·다른 꾸미기 삽입을 선행 조건으로 요구하지 않는다. 제목·본문 입력과 검증은 여전히 먼저 완료해야 한다.
- 선택한 항목은 네이버 화면에서 모두 펼쳐 표시한다. 실제 삽입은 각 버튼으로 명시적으로 실행하며 자동 발행하지 않는다.
- 서로 다른 꾸미기 삽입이 기존 완료 상태를 지워 중복 실행을 유도하지 않도록 상태 처리를 정리했다.
- 임시저장은 꾸미기 영역 다음에 둔다. 아직 삽입하지 않은 선택 항목이 있으면 저장 전 알린다.

## 블로그 세팅과 AI 연결

블로그 세팅 화면 아래에 기존 API 키 입력·보안 저장·연결 확인·키 삭제 UI를 재사용한다. ‘다음: AI 연결’은 같은 화면의 API 키 입력으로 이동한다. AI 연결 성공 후 ‘다음: 네이버 연결’로 이동한다. 네이버 로그인 계정과 등록 블로그를 확인한 후 ‘연결됐어요, 새 글 작성’으로 이어진다. 별도 메뉴, 중복 저장 로직, 새 서비스는 추가하지 않는다.

## 보존한 기능과 안전 경계

- 로그인·회원권·기기 제한·API 키 보안 저장·AI 생성 처리·네이버 자동화 어댑터·운영 데이터베이스는 변경하지 않는다.
- 사전 설정 전달·선택 항목 노출·완료 상태 관리와, 이번에 승인한 네이버 선연결·메뉴 간 상태 유지에 필요한 화면 제어만 확장한다.
- 외부 라이브러리나 유료 서비스를 추가하지 않는다.
- 실데이터 변경, 실제 유료 AI 생성, 실제 네이버 조작은 이번 UI 검수에서 실행하지 않는다.

## 디자인

흰색 작업면, 밝은 회색 바탕, 기존 파란색 강조와 내장 SUIT 글꼴을 유지한다. 작성 영역 간 32px(작은 화면 24px) 간격과 제목 구분선을 사용한다. 긴 화면에서도 데스크톱 메뉴와 상단 헤더를 유지한다. 작은 창에서도 가로 스크롤 없이 재배치한다.

## 메뉴 최종 확인 (2026-09-24)

기본 화면과 로고 이동 목적지를 블로그 세팅으로 맞추고, 대분류 없이 4개 메뉴를 순서대로 표시한다. 네이버 임시저장은 별도 메뉴가 아니라 새 글 작성의 마지막 단계다. 개발 전용 연결 진단은 일반 사용자 화면에 노출하지 않으며 기존 개발 모드에서만 목록 마지막에 유지한다. 인증·회원권·AI 생성·실제 네이버 조작을 담당하는 핵심 로직은 유지하며, 기존 연결 API의 실행 시점과 화면 내 상태 관리만 조정한다.

## 네이버 선연결과 작성 내용 유지 (2026-09-24)

- 프로그램 시작 화면은 블로그 세팅이다. 브랜드 정보 → AI 연결 → 네이버 연결 순서로 준비한다.
- 단계 표시는 네이버 연결 → 글 내용 입력 → 만들어진 글 확인 → 네이버 임시저장이다.
- 로그인된 실제 블로그가 등록한 블로그와 일치하고, 연결 오류가 없을 때 작성 화면을 사용할 수 있다. 입력한 주소만으로 연결 완료를 표시하지 않는다.
- 연결 준비 단계에서는 로그인과 블로그 확인까지만 수행한다. 글쓰기 편집기는 생성 결과를 검토한 뒤 사용자 버튼으로 연다.
- 편집기를 처음 열기 직전 기존 verify → openWriter 순서로 계정을 재확인한다. 이후 제목·본문 입력 및 저장 시 기존 어댑터의 검증을 그대로 적용한다.
- verify는 네이버 블로그 홈으로 이동하므로, 이미 편집 중인 화면을 자동으로 이탈시키지 않는다. 새로운 생성 결과로 교체할 때 새 편집기 진입은 사용자 확인을 받는다.
- 블로그 세팅·새 글 작성·연결 화면을 유지해 메뉴를 오가도 주제·키워드·모델·마지막 안내 문구·꾸미기·생성 결과·전송 단계가 사라지지 않게 한다.
- 직접 수정한 마지막 안내 문구는 저장된 브랜드 기본 문구를 다시 불러와도 덮어쓰지 않는다.
- 네이버 임시저장 중 다른 메뉴로 이동했다가 ‘새 글 작성’을 누르면 진행하던 저장 단계로 복귀한다. ‘글 확인으로 돌아가기’로 생성 결과를 다시 볼 수 있다.
- 연결 끊김 알림을 받으면 재연결 안내를 표시하고 작성 내용은 유지한다. 로그인 만료와 계정 불일치 상태에서는 편집기 진입을 차단한다.
- 작업 내역에서 기존 임시글을 여는 동작은 네이버 세션을 바꾸므로 기존 연결·삽입 완료 상태를 무효화한다. 현재 작성 내용은 유지하고 새 작업 전 재연결을 요구한다.
- 연결 조작 및 AI 생성 중에는 메뉴 이동을 잠시 막아 중복 조작을 방지한다. 기존 중단·취소 동작은 유지한다.
- 상태 유지는 현재 실행 중인 프로그램의 메모리 범위다. 프로그램 종료·미리보기 새로고침 후의 미저장 글 복구나 자동 영구 저장은 이번 범위에 포함하지 않는다.
- 브라우저 모의 회귀 검사 12개 통과: 기존 꾸미기 경로, 입력 보존·재연결, 로그인 만료·계정 불일치, 저장 1회, 새 글 확인, 예전 글 열기 후 상태 무효화, 반응형 검수 포함.
- 미리보기의 연결·작성은 예시 데이터이며 실제 네이버 로그인이나 유료 AI 호출을 수행하지 않는다. 실제 계정과 설치 프로그램의 통합 검수는 별도 필요하다.

## 블로그 세팅 세로형 입력 (2026-09-24)

- 브랜드명 → 업종 → 브랜드·사업 소개부터 전체 20개 입력 항목을 한 줄에 하나씩 세로로 배치한다.
- 운영 및 소개 정보, 글에 적용할 표현 기준, 연락 및 예약 정보, 이미지 기본 방향을 접기 없이 항상 표시한다.
- 각 영역에 제목·설명·입력 개수를 유지하고, 구분선과 여백으로 영역을 구분한다. 항목 간 간격은 28px이다.
- 필수 3개·선택 17개 구분, 저장 형식, 저장·불러오기, 입력값 검증과 AI·네이버 연결 기능은 변경하지 않는다.
- 추가 선택 정보는 전부 채울 필요가 없으며, 필요한 항목만 위에서 아래로 입력할 수 있다.

검증: 세로형 입력 모의 UI 검사 6개 통과(20개 항목 노출·키보드 순서·필수 입력·예약 링크 검증·저장값/메뉴 이동 보존·반응형 배치). 타입 검사와 기존 단위 테스트 214개 통과. 화면과 검수 결과는 work/ui-ux-v5/brand-stacked-*.png 및 brand-layout-results.json에 보관한다.

## 필수·선택 사항 분리 (2026-09-24, 최신 기준)

- 기존 필수 3개에 기본 말투, 주요 상품·서비스, 영업시간, 핵심 강점과 차별점, 주요 고객, 반드시 강조할 내용, 전화번호, 주소를 추가한다.
- 필수 사항 11개를 위에 모으고 선택 사항 9개를 아래에 둔다. 두 분류 제목은 24px의 굵은 제목으로 표시하고 구분선·여백으로 경계를 분명히 한다.
- 모든 입력은 한 줄에 하나씩, 접기 없이 표시한다. 개별 필드의 필수·선택 표시와 준비 상태의 입력 개수도 실제 분류와 일치시킨다.
- 화면과 로컬 저장 단계 모두 필수값 누락을 검사한다. 첫 누락 항목에 초점을 이동하고 각 필드 아래에 오류를 표시한다.
- 기존 저장 파일의 구조와 불러오기 규칙은 유지한다. 이전 프로필은 삭제·초기화하지 않으며 새로 필수가 된 값은 다음 저장 시 보완한다. 기존 글 생성·연결 기능은 변경하지 않는다.
- 전화번호와 주소는 브랜드의 공개 정보만 입력하도록 안내한다. 방문 장소가 없는 사업은 주소에 온라인 전용 등 실제 운영 형태를 설명할 수 있다.
- 이전의 필수 3개·선택 17개 기준 및 그 기준으로 작성한 검수 기록은 위의 최신 기준으로 대체한다.

검증: 단위 테스트 225개, 필수·선택 세로형 폼 UI 검사 7개, 기존 글쓰기·연결 모의 검사 12개, 전체 타입 검사·빌드·변경 형식 검사 통과. 실제 외부 서비스 호출 없이 예시 데이터로 검사했다. 필수 누락 시 기존 저장 파일이 덮어써지지 않는 것도 확인했다. 화면 검수: work/ui-ux-v5/brand-required-*.png, 결과: brand-required-results.json.


## 글 주제 AI 추천 (2026-09-24)

- 새 글 작성의 ‘쓰고 싶은 내용’ 아래에 ‘내용 작성 추천 받기’를 둔다. 사용자가 짧은 주제를 입력한 뒤 직접 누를 때만 요청한다.
- 이미 연결한 본인의 OpenAI API 키를 기존 보안 저장소에서 읽어 사용한다. 키를 화면으로 전달하거나 요청 본문·로그에 기록하지 않는다.
- 현재 선택한 사용 가능 모델·사고 수준을 우선 사용한다. 선택 전이면 사용 가능 기본 모델과 낮은 사고 수준(지원되지 않으면 해당 모델의 첫 지원값)을 사용하고 추천 버튼 아래에 모델명을 표시한다.

## 상품·서비스 별도 저장 및 블로그 세팅 정리 (2026-09-25)

- 블로그 세팅의 ‘주요 상품·서비스’를 기본 입력 폼에서 분리했다. 항목마다 입력란을 제공하고 추가·수정·삭제 후 ‘상품·서비스 저장’으로 목록만 저장한다.
- 최초에는 필수 기본 정보 10개를 입력하고 ‘블로그 세팅 저장’을 누른다. 이후 상품·서비스를 독립적으로 저장할 수 있다. 별도 목록 저장에는 최소 1개 항목이 필요하다. 기본 정보의 이전 11개 필수 기준은 ‘기본 정보 10개 + 별도 상품 목록’으로 대체한다.

## 인용구·스티커·구분선 횟수 및 구간 배치 (2026-09-25)

- 세 꾸미기 항목의 첫·마지막 문단 및 문단 앞·뒤 직접 선택을 제거했다. 새 글 작성과 네이버 임시저장 화면에 동일한 ‘배치 설정’을 제공한다.
- ‘횟수로 자동 배치’: 각 종류별 1–5회를 선택한다. 글 전체에 나누어 배치한다.
- ‘상·중·하로 지정’: 상단·중단·하단 중 하나 이상을 선택하며 각 선택 구간에 한 번씩 삽입한다. 구간의 체크 순서와 관계없이 본문 순서로 실행한다.
- 실제 위치는 글자 수로 본문 길이를 계산한 뒤 가까운 기존 문단 경계로 정한다. 문장을 중간에 자르지 않고, 같은 종류를 같은 경계에 중복 배치하지 않는다. AI가 내용을 해석해 위치를 판단하는 기능은 아니며 추가 AI 호출·요금은 없다.
- 두 문단 이상이면 본문 내부의 문단 사이만 사용한다. 한 문단뿐이면 문단 뒤에 최대 한 번 배치한다. 요청보다 위치가 부족하면 실제 횟수와 조정 이유를 삽입 전에 표시한다.
- 원래 네이버 삽입 어댑터와 IPC 요청 형식은 유지했다. 위치 하나를 삽입·검증한 뒤 다음 위치를 순차 처리하므로 본문 기준·디자인·묶음·개수·삽입 위치의 기존 검증이 유지된다.
- 인용구의 기존 디자인 삽입 방식은 유지하며 별도 인용문 생성 기능을 추가하지 않는다. 디자인은 선택값 또는 지원 목록 내 무작위 방식, 스티커는 선택 묶음 안에서 위치마다 무작위 방식으로 동작한다.
- 실행 중 입력·메뉴 이동·중복 클릭을 막고, 완료 횟수를 종류별로 유지한다. 종류가 다른 꾸미기를 실행해도 기존 완료 기록을 지우지 않는다.
- 중간 오류는 확인된 횟수까지만 표시하고 이후 삽입을 멈춘다. 결과가 불확실한 배치를 재시작하지 않으며 다른 작업이 오류 메시지를 해제해도 재시도 차단은 유지한다. 사용자는 Chrome 결과를 확인하고 새 작업으로 다시 시작해야 한다.
- 작업 중단·다른 임시글 열기·새 편집기 시작 시 이전 비동기 결과로 다음 삽입을 시작하지 않는다. 새로운 글 또는 새 입력 작업에서는 진행 상태를 초기화한다.
- UI/UX 지침에 맞춰 배치 방식·횟수·구간을 명확히 분리하고, 다중 선택·실제 횟수·짧은 글 안내·완료 및 부분 완료 상태를 표시한다. 키보드 조작, 작은 화면, 글자 확대를 지원한다.

## 랜덤 배치 횟수 1–10회와 문맥 단서 적용 (2026-09-26)

이번 규격은 위의 ‘횟수 및 구간 배치’에서 1–5회·상중하·내부 문단만 사용하는 규칙을 대체한다.

- 새 글 작성과 네이버 임시저장의 인용구·스티커·구분선에서 배치 방식 및 상·중·하 선택을 제거했다. 각 항목의 삽입 횟수를 독립적으로 1–10회 선택한다. 사용 안 함과 기존 디자인·스티커 묶음 선택은 유지한다.
- 일반적인 무작위 위치 선택 대신 내용 전환 표현(다음으로·이어서·한편 등), 다음 소제목 앞, 요약·마무리 표현이 있는 문단 뒤를 우선 후보로 삼는다. 적합성이 같은 후보 중에서는 무작위로 고르고, 가능한 경우 바로 인접한 위치를 피한다.

## 단일·여러 글 자동 작성 및 네이버 임시저장 (2026-09-27)

이 규격은 앞선 ‘생성 결과를 사용자가 확인하고 임시저장 화면으로 이동’하는 정상 작성 흐름을 대체한다.

- 한 글도 여러 글도 글별 설정 → 실행 전 비용 확인 → 자동 생성·형식 검사 → 네이버 입력·이미지·꾸미기 → 임시저장 확인 → 마지막에 사용자 검토 순서로 처리한다. 중간 단계의 반복 확인 버튼은 사용하지 않는다. 최종 발행은 자동화하지 않는다.
- 새 글 작성에 ‘자동 작성 목록’을 추가한다. 각 항목은 주제·유형·길이·키워드·상품 선택·모델·추론 강도·이미지 설정·인용구·스티커·구분선 설정과 대상 블로그를 독립적으로 보관한다. 브랜드 기본 정보는 실행 시 기존 저장 프로필을 사용한다.
- ‘목록에 추가’로 글을 준비하고 대기 항목의 설정을 수정·삭제할 수 있다. ‘목록 전체 자동 작성·저장’은 대기 항목을 순서대로 처리한다. ‘이 글 자동 작성·저장’은 현재 설정한 한 글만 처리하며 다른 대기 글은 실행하지 않는다.
- 실행 전 글 수·이미지 수·개인 API 비용·PC 전원 및 조작 금지·사후 검토 필요성을 안내하고 확인받는다. 목록 저장 자체는 AI 요청을 하지 않는다.
- 목록은 계정별 로컬 저장소에 최대 20개까지 저장한다. API 키와 이미지 데이터는 포함하지 않는다. 재시작 후 대기 항목은 수동 시작을 기다리고, 실행 중이던 항목은 중단으로 표시한다. 실패·중단·완료 항목은 자동 재시도하지 않는다.
- 기존 AI 생성·검증, 네이버 단일 입력·이미지·꾸미기·임시저장 함수를 재사용한다. 인증·회원권·관리자·운영 데이터베이스·AI 모델 목록·생성 프롬프트·네이버 최종 발행 코드는 변경하지 않는다.
- 매 글마다 전용 Chrome의 새 탭에서 실제 로그인 계정과 대상 블로그를 먼저 재확인한다. 이전 편집 탭을 지우거나 덮어쓰지 않는다. 기존 빈 편집기 검사와 사용자 조작 감지 안전장치를 유지한다. 작성 탭은 확인용으로 남기므로 여러 글 실행 시 Chrome 메모리 사용량이 증가할 수 있다.
- 형식 자동 검사에서 조건을 충족하지 못하거나 이미지가 누락되거나 선택한 꾸미기가 없으면 임의의 대체나 추가 유료 재시도를 하지 않고 중단한다. 형식 검사는 사실관계·광고 적합성·저작권을 보증하지 않는다.
- 스티커 묶음 직접 지정 시 실행 전에 네이버에 표시되는 정확한 묶음 이름을 입력한다. 실행 중 실제 목록과 유일하게 일치해야 하며 일치하지 않으면 멈춘다.
- 꾸미기의 1–10회 제한과 내용 전환·마무리 단서 기반 랜덤 위치 계산을 유지한다. 적절한 위치가 부족하면 가능한 횟수만 삽입하고 완료 결과에 실제 횟수를 표시한다. 생성 이미지는 기존 개별 이미지 배치로 삽입한다.
- 단계마다 진행 상황을 먼저 저장하고 외부 작업을 실행한다. 저장소 오류·네이버 오류·로그인 만료·사용자 중단 시 이후 글도 멈춘다. 진행 중이던 네이버 요청은 결과가 돌아올 때까지 기다리며, 중단 요청 뒤 새 단계는 시작하지 않는다.
- 네이버 저장이 확인된 뒤 작업 내역을 기록한다. 중단과 저장 완료가 겹치거나 로컬 작업 내역 기록에 실패해도 이미 저장된 글은 다시 저장하지 않는다. 불확실한 저장은 성공으로 표시하지 않는다.
- 완료 후 ‘저장한 글 확인’에서 기존 작업 내역을 열고 네이버 임시저장 글을 검토한다. 실패한 글의 생성 텍스트는 목록에서 복구 확인할 수 있다.
- 최소 변경 스킬에 따라 기존 연결 통로를 재사용하고 새 의존성을 추가하지 않았다. UI/UX 스킬에 따라 별도 제목·간격, 텍스트 상태 표시, 실행 중 입력 및 메뉴 잠금, 오류 안내, 키보드·작은 화면 지원을 적용했다.
