# BLOW MVP 결정 001 — 네이버 자동 입력 정책

> 확인일: 2026-09-09
> 상태: 사용자 측 외부 자문 완료 — 이 작업에서 추가 문의·검토하지 않음
> 적용 범위: 네이버 로그인, 편집기 입력, 임시저장과 발행 자동화
> 성격: 공식 문서 기반 초기 위험 판단 기록이며 후속 자문 결과는 사용자 측 보관

## 1. 결정

네이버 자동화 관련 정책 문의와 자문은 사용자가 별도 작업에서 완료했다. 이 저장소에서는 같은 문의를 반복하지 않으며, 이후 개발은 사용자가 확정한 허용 범위와 운영 기준을 전제로 진행한다.

POC는 기술적으로 통과했지만, 네이버 공식 이용약관에서 사전 허락 없는 자동화 이용과 자동화 수단에 의한 콘텐츠 삽입을 금지하고 있다. 최종 발행을 사용자가 직접 하더라도 BLOW가 제목·본문·이미지를 자동으로 편집기에 삽입하고 임시저장하는 과정이 금지 조항에 포함될 가능성이 높다.

구체적인 자문 내용과 증빙은 사용자 측에서 보관한다. 실제 출시 전에는 구현 범위가 사용자가 확정한 운영 기준과 일치하는지만 최종 확인한다.

## 2. 공식 근거

### 2.1 네이버 서비스 이용약관

2025년 7월 10일 시행 약관은 다음 행위를 금지한다.

- 사전 허락 없이 자동화된 수단으로 로그인, 게시물 게재 등 실제 사람의 이용을 전제로 한 기능을 이용하는 행위
- 네이버의 동의 없이 자동화된 수단으로 네이버 서비스 영역에 콘텐츠나 파일을 삽입하는 행위
- CAPTCHA 등 자동화 방지 기술을 우회하거나 무력화하는 행위

근거: [네이버 서비스 이용약관](https://policy.naver.com/policy/service.html)

### 2.2 네이버 이용제한 고객센터

네이버는 사전 허락 없이 매크로·봇 등 자동화 수단으로 게재한 게시물을 제한 대상이라고 안내한다. 허락하지 않은 자동화 수단을 판매·홍보하는 게시물도 제한 대상으로 설명한다.

근거: [비정상적인 서비스 이용](https://help.naver.com/service/19212/contents/14953?lang=ko&osType=COMMONOS)

### 2.3 공개 API 범위

현재 네이버 오픈 API 목록에는 블로그 검색과 공유 기능은 있지만 블로그 글쓰기 API는 없다. 공개적으로 지원되는 블로그 작성 연동 경로를 확인하지 못했다.

근거: [네이버 오픈 API 목록](https://developers.naver.com/products/intro/plan/plan.md)

### 2.4 대량·기계적 게시물 위험

네이버 검색 고객센터는 홍보 또는 검색 품질 저하를 목적으로 게시물을 기계적으로 대량 생산하는 경우 검색 결과에서 제한될 수 있다고 안내한다. CAPTCHA 안내에서도 게시물을 천천히 등록하라고 권고한다.

근거:

- [블로그 게시글 노출 안내](https://help.naver.com/service/5626/contents/22924?lang=ko&osType=COMMONOS)
- [보안 CAPTCHA가 노출되는 경우](https://help.naver.com/service/5593/contents/15411?lang=ko&osType=COMMONOS)

## 3. BLOW에 미치는 영향

| BLOW 동작 | 정책 위험 판단 | 이유 |
|---|---|---|
| 전용 Chrome 열기 | 낮음 | 사용자가 직접 Chrome을 여는 것과 유사하지만 후속 자동화와 결합된다. |
| 사용자의 수동 로그인 | 낮음 | BLOW가 아이디·비밀번호를 입력하거나 인증을 우회하지 않는다. |
| 글쓰기 화면 자동 진입 | 중간 | 사람의 실제 이용을 전제로 한 기능을 자동 조작한다. |
| 제목·본문·이미지 자동 입력 | 높음 | 자동화 수단에 의한 콘텐츠 삽입 금지 조항과 직접 관련된다. |
| 임시저장 자동 조작 | 높음 | 네이버에 콘텐츠를 저장하는 자동 조작이다. |
| 사용자의 최종 발행 | 위험을 제거하지 못함 | 앞선 자동 입력·저장이 이미 자동화로 수행된다. |
| CAPTCHA·본인인증 우회 | 금지 | BLOW에서도 구현하지 않으며 즉시 중단해야 한다. |

## 4. 예상 위험

- 사용자 네이버 계정의 글쓰기·로그인 또는 서비스 이용 제한
- 게시물 비공개·삭제 또는 검색 노출 제한
- Chrome 자동화 변경에 따른 반복 장애
- 유료 사용자 피해, 환불과 고객지원 비용
- 네이버의 중지 요청이 발생했을 때 제품 핵심 기능 전체 중단

이 위험은 앱에 경고문을 표시하거나 최종 발행을 사용자에게 맡기는 것만으로 제거되지 않는다.

## 5. 네이버에 확인할 질문

1. 사용자가 본인 PC에서 직접 실행하고 직접 로그인하는 보조 프로그램이 블로그 편집기에 제목·본문·이미지를 입력하는 행위가 허용되는가?
2. 프로그램이 최종 발행을 누르지 않고 임시저장까지만 수행해도 허용되는가?
3. 사용자가 각 작업을 직접 시작하고 진행 중 개입하면 즉시 멈추는 방식도 사전 허락이 필요한가?
4. 유료 소프트웨어로 판매할 경우 필요한 제휴·API 계약 또는 별도 심사가 있는가?
5. 허용되는 호출 빈도, 게시물 수, 자동화 범위와 필수 사용자 고지는 무엇인가?
6. 허용받았음을 증명할 수 있는 서면 또는 계약 문서를 받을 수 있는가?

## 6. 문의 경로

네이버 회사 홈페이지의 제휴 제안에서 다음과 같이 제출한다.

1. [네이버 제휴 제안 작성](https://navercorp.com/company/partnerApply?joinSiteCd=ADV) 페이지를 연다.
2. 제휴 희망 영역에서 “기술·API 제휴” 또는 “서비스·콘텐츠 제휴”를 선택한다.
3. 제안 제목은 “사용자 PC 기반 네이버 블로그 작성 보조 프로그램의 허용 범위 문의”로 작성한다.
4. 위 여섯 가지 질문과 “사용자 직접 로그인·최종 발행, CAPTCHA 우회 없음”을 명시한다.
5. 제품의 핵심 기술, 비밀번호, API 키, 네이버 계정 정보와 영업비밀은 첨부하지 않는다.
6. 제출 후 발급되는 제안 등록번호를 별도로 보관한다.

네이버는 제안을 검토하더라도 회신이나 수락 의무가 없다고 안내한다. 답변이 없다는 사실을 허락으로 해석해서는 안 된다.

## 7. 문의용 초안

### 제목

사용자 PC 기반 네이버 블로그 작성 보조 프로그램의 허용 범위 문의

### 내용

안녕하세요. 네이버 블로그를 직접 운영하는 사용자를 위한 Windows 작성 보조 프로그램을 검토하고 있습니다.

사용자는 자신의 PC에서 프로그램을 직접 실행하고, 별도의 Chrome 프로필에서 네이버 로그인을 직접 완료합니다. 프로그램은 사용자가 입력한 원고와 이미지를 네이버 블로그 편집기에 옮기고 임시저장까지만 수행하는 구조를 검토 중입니다. 프로그램은 네이버 아이디·비밀번호를 수집하거나 저장하지 않으며, CAPTCHA·본인인증을 우회하지 않습니다. 추가 인증이나 예상하지 못한 화면이 나타나면 즉시 중단하고, 최종 발행은 사용자가 직접 수행합니다.

이 방식도 네이버 서비스 이용약관상 사전 허락이 필요한 자동화 또는 콘텐츠 삽입에 해당하는지 확인을 요청드립니다. 유료 소프트웨어로 제공할 때 필요한 제휴, 계약, 심사, API 사용 방식과 허용되는 자동화 범위가 있다면 안내 부탁드립니다. 특히 자동 입력, 이미지 첨부, 임시저장과 사용자 직접 발행 각각의 허용 여부를 서면으로 확인하고 싶습니다.

감사합니다.

## 8. 답변에 따른 다음 경로

### 서면 허용

- 허용 범위와 제한을 PRD·이용약관·자동화 코드에 반영한다.
- 허용받지 않은 동작은 제거한다.
- 별도 계약, 비용 또는 심사 조건은 사용자 승인 후 진행한다.
- M0의 서버·인증 공급자 결정으로 이동한다.

### 조건부 허용

- 조건을 비용, 운영 부담과 핵심 가치에 대조한다.
- 조건을 만족하는 축소 MVP를 다시 확정한다.
- 계약·비용이 있으면 승인 전 결제하지 않는다.

### 거절 또는 무응답

- 네이버 화면 자동 조작 기능은 출시 범위에서 제외한다.
- BLOW는 글·이미지 생성과 구성 안내까지만 제공한다.
- 사용자가 직접 복사, 붙여넣기, 이미지 첨부와 임시저장을 수행하는 방식으로 제품을 재설계한다.

## 9. 즉시 적용할 안전조치

- 네이버 서면 답변 전에는 공개 판매와 외부 사용자 배포를 시작하지 않는다.
- 실제 고객·운영 계정으로 추가 자동화 테스트를 진행하지 않는다.
- CAPTCHA·본인인증·로그인 보호 절차 우회 기능을 개발하지 않는다.
- POC 코드와 결과는 기술 자료로 보존하되 제품 기능 확정으로 간주하지 않는다.
