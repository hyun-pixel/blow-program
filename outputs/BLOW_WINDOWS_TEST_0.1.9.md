# BLOW 0.1.9 — 스티커 연속 삽입 확인 보완

## 확인한 범위와 한계

- 사용자 화면은 다섯 번째 스티커 삽입 시도 중 `STICKER_INSERT_UNCONFIRMED`로 중단된 상태였습니다. 실제 다섯 개가 들어갔다는 뜻은 아닙니다.
- 당시 네이버 창이 닫혀 실제 DOM·네트워크 상태는 확인하지 못했습니다. 따라서 사용자 오류의 직접 원인을 확정하지 않습니다.
- 기존 코드는 모든 프레임에서 표시 중인 스티커 수를 비교했습니다. 기존 스티커의 표시 상태가 바뀌거나 새 스티커 표시가 5초보다 늦으면 오판할 수 있습니다.
- 격리된 테스트 화면에서 다섯 번째 삽입 때 기존 스티커 하나의 표시 상태가 바뀌는 조건을 만들었습니다. 수정 전 코드가 1~4회 성공 후 5회에서 같은 오류로 실패함을 확인했고, 수정 후 6회를 완료했습니다. 이 조건은 로컬 재현 조건이며 당시 네이버가 그렇게 동작했다는 증거는 아닙니다.

## 수정 내용

- 삽입 직전의 스티커 요소와 ID를 기억하고, 같은 편집 문서에서 새 요소 하나가 추가됐는지 검사합니다. 기존 요소가 다시 그려져도 ID가 유지되면 같은 스티커로 취급합니다.
- 기존 스티커 보존, 정확히 한 개 증가, 새 스티커 표시 및 이미지 로딩 완료를 확인합니다. 본문 원문과 앞·뒤 위치 검증은 유지합니다.
- 새 스티커 확인 대기를 기존 5초에서 10초로 늘렸습니다. 메뉴 탐색 대기는 변경하지 않았습니다.
- 확인이 늦어져도 스티커 버튼을 다시 누르지 않습니다. 실제 미삽입·중복 삽입·새 스티커 미표시·이미지 오류·위치 오류는 성공 처리하지 않습니다.
- 오류 메시지에 삽입 전·현재 감지·기대 개수를 남깁니다. 사용자 중단 신호는 계속 적용합니다.
- ponytail 원칙에 따라 기본 삽입과 무작위 삽입이 같은 검증 함수를 사용하도록 수정했습니다. AI 모델·생성 조건·UI 디자인·저장 및 발행 정책은 변경하지 않았습니다.

## 사용자 확인 순서

1. BLOW와 BLOW 전용 Chrome을 닫습니다.
2. 아래 0.1.9 설치파일로 기존 설치에 업데이트합니다. **기존 BLOW를 먼저 제거하지 마세요.** 제거 시 로컬 설정·프로필이 삭제될 수 있습니다.
3. 블로그 연결을 확인한 뒤 스티커 6개를 설정한 글 한 건만 먼저 실행합니다.
4. 임시저장 완료와 작업 내역을 확인하고, 네이버에서 실제 스티커 수를 확인합니다. 자동 발행은 하지 않습니다.
5. 다시 실패하면 삽입 전·현재 감지·기대 개수가 포함된 메시지를 캡처합니다. 기존 항목을 재생성하면 AI 비용이 다시 발생할 수 있습니다.
