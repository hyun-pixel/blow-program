# BLOW MVP 구현 실행계획 v1.0

> 작성 기준일: 2026-09-09
> 문서 상태: 개발 착수 전 범위 확정안
> 기준 문서: `BLOW_PRD_v1.0.md`, `BLOW_UIUX_SCREEN_SPEC_v1.0.md`, `BLOW_NAVER_AUTOMATION_POC_RESULT_v1.0.md`

## 1. 목표

네이버 자동 입력 POC에서 확인한 기능을 재사용해, 비개발자가 글을 생성하고 네이버 임시글로 안전하게 저장할 수 있는 Windows MVP를 만든다. MVP는 최종 발행을 수행하지 않으며, 계정·이용권·보안·오류 대응과 운영자 관리 기능까지 포함해야 한다.

이번 계획은 기존 PRD를 대체하지 않는다. PRD의 P0 요구사항을 실제 개발 단위와 통과 조건으로 분해한 실행 기준이다.

## 2. 확정된 범위

### 2.1 MVP에 포함

- 이메일 회원가입, 인증, 로그인, 비밀번호 재설정과 탈퇴
- 수동 입금 기반 30일 이용권과 관리자 기간 설정
- 한 계정·한 PC·한 네이버 블로그 제한
- 전용 Chrome 프로필과 사용자 직접 네이버 로그인
- 사용자 OpenAI API 키의 로컬 암호화 저장·검사·교체·삭제
- 브랜드 프로필과 새 글 작성
- 제목·본문·이미지 생성과 작성 규칙 검사
- 개별사진·콜라주·슬라이드
- 스티커 카테고리 선택 후 카테고리 안에서 무작위 선택
- 인용구·구분선의 디자인, 개수와 위치 설정
- 네이버 편집기 입력과 임시저장
- 사용자 개입, 인증 만료, 네트워크·화면 변경 시 안전 중단
- 로컬 작업 내역 30일 보관과 네이버 임시글 열기
- 별도 관리자 웹의 회원·이용권·운영 중지·버전·감사 기록
- Windows 설치·제거, 필수 업데이트 안내와 긴급 자동화 중지

### 2.2 MVP에서 제외

- 네이버 최종 발행, 예약 발행과 대량 발행
- 네이버 아이디·비밀번호 수집 또는 저장
- 글꼴, 글자 크기와 글 정렬 변경
- 여러 블로그, 여러 PC와 팀 협업
- 자동 결제·환불과 자동 업데이트
- 업종별 규정 RAG, 성과 분석과 macOS·모바일 앱
- 토큰 수, 예상 API 비용과 실제 API 비용 표시·저장
- CAPTCHA, 본인인증 또는 네이버 로그인 보호 절차 우회

## 3. 기능 요구사항

| ID | 요구사항 | 완료 판단 |
|---|---|---|
| F-01 | 계정과 이메일 인증 | 가입부터 로그인, 재설정과 탈퇴 흐름이 동작한다. |
| F-02 | 이용권과 기기 제한 | 유효한 이용권과 등록 PC에서만 핵심 기능이 열린다. |
| F-03 | 네이버 블로그 연결 | 전용 Chrome에서 로그인한 블로그와 등록 주소가 일치해야 한다. |
| F-04 | OpenAI 연결 | API 키는 로컬에 암호화되고 서버·로그에 전송되지 않는다. |
| F-05 | 브랜드·글 입력 | 필수값, 글자 수, 키워드와 CTA 충돌을 API 호출 전에 검사한다. |
| F-06 | 콘텐츠 생성 | 허용 모델로 제목·본문·이미지를 만들고 결과 규칙을 다시 검사한다. |
| F-07 | 편집 구성 | 이미지 배치, 스티커, 인용구와 구분선 설정을 작업 계획으로 만든다. |
| F-08 | 네이버 자동 입력 | 검증된 어댑터가 제목부터 임시저장까지 순서대로 수행한다. |
| F-09 | 안전 중단 | 사용자 개입이나 예상하지 못한 화면이 나타나면 남은 조작을 중단한다. |
| F-10 | 로컬 기록 | 작업 상태와 결과를 정해진 기간만 보관하고 사용자가 삭제할 수 있다. |
| F-11 | 관리자 운영 | 회원, 이용권, 버전, 긴급 중지와 허용 모델을 감사 기록과 함께 관리한다. |
| F-12 | 설치·제거 | 설치, 업데이트 안내, 제거와 탈퇴 후 삭제 기준을 만족한다. |

## 4. 기술·보안 제약

| ID | 제약 |
|---|---|
| T-01 | 기존 Electron·React·TypeScript 구조와 `automation-core`, `naver-adapter`를 재사용한다. |
| T-02 | 사용자 콘텐츠, 원본 이미지, OpenAI API 키와 네이버 세션은 BLOW 서버로 보내지 않는다. |
| T-03 | API 키는 Windows DPAPI 또는 동등한 OS 보안 저장소로 보호한다. |
| T-04 | Electron은 `contextIsolation`과 sandbox를 켜고 `nodeIntegration`을 끈다. |
| T-05 | 일반 사용자 API와 관리자 API를 분리하고 관리자 MFA와 감사 기록을 적용한다. |
| T-06 | 자동화는 예상 화면과 대상 요소를 확인한 뒤에만 조작하며 임의 좌표 대체를 금지한다. |
| T-07 | 발행 버튼은 자동화 대상에 포함하지 않고 회귀 테스트로 금지 상태를 확인한다. |
| T-08 | MVP 초기 지원 브라우저는 최신 정식 Chrome이다. 직전 정식 버전은 별도 검증 후 추가한다. |
| T-09 | [추론] 새 서버·인증·이메일 서비스는 공급자, 비용과 개인정보 처리 위치를 승인받은 뒤 도입한다. |

## 5. 디자인 제약

| ID | 제약 |
|---|---|
| D-01 | 기존 UI·UX 화면 명세와 고밀도 업무용 대시보드 구조를 유지한다. |
| D-02 | 비개발자가 이해할 수 있는 한국어 상태와 다음 행동을 함께 표시한다. |
| D-03 | 오류는 색상만으로 구분하지 않고 아이콘, 제목과 설명을 함께 사용한다. |
| D-04 | 진행 중 사용자가 Chrome을 조작하면 실제 작업을 멈추고 중단 상태를 표시한다. |
| D-05 | 글꼴, 글자 크기와 정렬은 네이버 사용자 기본 설정을 따른다고 연결 단계에서 안내한다. |
| D-06 | 자동 입력 성공과 확인 불가를 구분하고, 확인 불가는 성공으로 기록하지 않는다. |

## 6. 개발 단계와 종료 조건

### M0. 범위·외부 결정 확정

현재 상태: 네이버의 서면 허락 전까지 상용 자동 입력 개발·출시를 보류한다. 근거와 문의 절차는 `BLOW_MVP_DECISION_001_NAVER_AUTOMATION_POLICY_v1.0.md`를 따른다.

작업:

- 네이버 정책과 상용화 가능성 검토
- 서버, 데이터베이스, 이메일 인증과 관리자 MFA 공급자 결정
- 개인정보처리방침, 이용약관, 환불 기준과 자동화 위험 고지 검토
- Windows 코드 서명과 배포 방식·비용 확인

종료 조건:

- 유료 서비스와 개인정보 처리 위치가 문서로 승인된다.
- 정책상 출시 불가 조건과 운영 중단 기준이 정해진다.
- 외부 서비스 비밀정보를 저장할 환경변수와 배포 권한 담당자가 정해진다.

### M1. 계정·이용권·기기·관리자 기반

작업:

- 사용자 인증과 이메일 인증
- 이용권 시작일·종료일·상태
- 최초 PC 등록, 변경과 차단
- 관리자 로그인·MFA, 회원 검색, 이용권 변경과 감사 기록
- 앱 버전, 필수 업데이트와 긴급 자동화 중지 설정

종료 조건:

- F-01, F-02와 F-11의 P0 흐름을 자동 테스트한다.
- 관리자 변경 전·후 값, 관리자와 시각이 감사 기록에 남는다.
- 만료·차단·기기 불일치 상태에서 글 생성과 자동 입력이 열리지 않는다.

### M2. 로컬 보안·연결 기반

작업:

- 로컬 데이터베이스와 보존 기간
- OpenAI API 키 보안 저장소
- 전용 Chrome 프로필과 등록 블로그 연결
- 로그의 API 키·콘텐츠·개인정보 마스킹

종료 조건:

- API 키 평문이 파일, 서버 요청과 로그에 없다.
- 네이버 로그인 정보는 앱에서 입력받지 않는다.
- 다른 PC 또는 다른 블로그는 안전하게 차단된다.

### M3. 앱 셸·온보딩·기본 설정

작업:

- 로그인·이용권 차단 화면
- 계정, 블로그, OpenAI, 브랜드, 위험 고지 온보딩
- 홈, 연결 설정, 계정과 도움말 화면
- 네이버 기본 글꼴·크기·정렬 설정 안내

종료 조건:

- 처음 사용하는 비개발자가 도움 없이 온보딩을 완료한다.
- 중간 종료 후 완료된 단계만 안전하게 이어진다.
- 키보드만으로 핵심 화면을 이동할 수 있다.

### M4. 글 작성·생성·규칙 검사

작업:

- 브랜드 프로필과 새 글 작성 폼
- 허용 모델·추론 강도 선택
- 제목·본문 생성과 규칙 검사
- 충돌 사전 검사, 취소, 실패와 수동 재시도

종료 조건:

- 제목, 본문 길이, 키워드와 CTA 수용 기준을 통과한다.
- 제공되지 않은 가격·경력·통계·출처 생성을 검사한다.
- 실패 후 사용자 입력값이 유지되고 자동 재시도하지 않는다.

### M5. 이미지·편집 구성

작업:

- 사용자 이미지 첨부와 생성 이미지
- 개별사진·콜라주·슬라이드 계획
- 스티커 카테고리·무작위 항목, 인용구와 구분선 설정
- 콘텐츠 블록 기준 개수·위치 모델

종료 조건:

- 선택한 이미지 장수와 배치가 작업 계획과 일치한다.
- 원본 첨부파일은 수정하거나 앱 정리 대상으로 취급하지 않는다.
- 스티커·인용구·구분선 개수와 위치를 결정적으로 재현할 수 있다.

### M6. 네이버 어댑터 제품 통합

작업:

- POC 어댑터를 실제 작성 작업 모델과 연결
- 화면·요소 사전 검증, 진행 상태와 취소
- 제목, 본문, 이미지, 서식과 임시저장
- 사용자 개입·인증 만료·네트워크·화면 변경 안전 중단

종료 조건:

- POC 핵심 시나리오가 제품 흐름에서 다시 통과한다.
- 임시저장 완료를 확인한 경우에만 성공으로 기록한다.
- 어떤 경로에서도 최종 발행을 조작하지 않는다.
- 중단 뒤 남은 자동 입력이 실행되지 않는다.

### M7. 기록·삭제·설치

작업:

- 작업 내역, 로컬 보존 기간과 개별 삭제
- 네이버 임시글 열기
- 비정상 종료 뒤 미완성 작업 정리
- Windows 설치, 수동 업데이트 안내, 제거와 탈퇴 삭제

종료 조건:

- 생성 이미지 7일, 본문과 작업 내역 30일 보존 기준을 검증한다.
- 앱 데이터 삭제가 사용자 원본 파일을 삭제하지 않는다.
- 제거·탈퇴 뒤 BLOW 전용 자격증명과 로컬 데이터가 남지 않는다.

### M8. 출시 전 통합 검증

작업:

- 최신 정식 Chrome, Windows 지원 범위와 화면 배율 검증
- 네트워크 지연·단절, 인증 만료, 화면 구조 변경과 강제 종료
- 서버 요청·로그·관리자 권한 보안 검사
- 비개발자 5명 선행 배포와 오류 수정

종료 조건:

- PRD의 P0 수용 기준과 보안 점검표가 모두 통과한다.
- 치명적 오류가 없고 복구·긴급 중지 절차를 운영자가 실행할 수 있다.
- 5명 선행 배포 결과를 검토한 뒤 20명 확대 여부를 별도로 승인한다.

## 7. 주요 수용 기준

1. 사용자는 유효한 계정·이용권·등록 PC에서만 새 글 작업을 시작할 수 있다.
2. 서버에는 OpenAI API 키, 네이버 세션, 글, 참고자료와 이미지가 저장되거나 기록되지 않는다.
3. 생성 결과는 제목·본문·키워드·CTA 규칙을 만족하거나 명확한 수정 상태로 남는다.
4. 이미지와 서식 설정은 네이버 편집기 결과와 일치한다.
5. 네이버 임시저장은 완료 신호가 확인된 경우에만 성공이다.
6. 사용자 개입, 추가 인증, 네트워크 단절과 화면 변경 때 남은 자동 조작이 멈춘다.
7. 최종 발행은 코드, UI와 테스트 어디에도 자동 동작으로 존재하지 않는다.
8. 탈퇴·제거는 BLOW 전용 데이터를 지우되 사용자 원본 파일은 보존한다.
9. 관리자 중요 변경은 MFA와 감사 기록을 거친다.
10. 최신 정식 Chrome의 지원 시나리오와 Windows 배율·해상도 기준을 통과한다.

## 8. 예외·경계 조건

- E-01: 이메일 인증 링크 만료·중복 사용
- E-02: 이용권 만료 중 작업 진입 또는 관리자 기간 변경
- E-03: 등록 PC 교체, OS 재설치와 기기 식별값 변화
- E-04: 다른 네이버 계정 또는 다른 블로그로 로그인
- E-05: API 키 오류, 한도·잔액 부족과 모델 지원 종료
- E-06: 참고 URL 접근 불가, 첨부파일 손상과 이미지 일부 실패
- E-07: Chrome 업데이트, 확장 기능 간섭과 로그인 보호 절차

## 11. 권장 다음 작업

네이버 제휴 제안을 통해 자동 입력 허용 범위를 서면으로 확인해야 한다. 서버·데이터베이스는 `BLOW_MVP_DECISION_002_BACKEND_HOSTING_v1.0.md`에 따라 Supabase 서울 리전으로 확정했다. 인증 메일은 `BLOW_MVP_DECISION_003_AUTH_EMAIL_v1.0.md`에서 Amazon SES 서울 리전을 권장했으며 사용자 승인 전에는 계정·결제·DNS 변경을 하지 않는다. 다음으로 관리자 MFA 방식을 확정하고, 네이버 서면 허락 후 계정·이용권·기기 제한과 관리자 기본 기능을 별도 구현 브랜치에서 시작한다.

POC 브랜치는 네이버 어댑터의 검증 기준점으로 보존한다. MVP 통합 시에는 기존 어댑터를 복사해 새 구현을 만드는 대신 패키지 의존성으로 재사용하고, POC 회귀 테스트를 제품 통합 테스트에 포함한다.
