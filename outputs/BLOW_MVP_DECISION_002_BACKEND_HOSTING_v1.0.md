# BLOW MVP 결정 002 — 서버·데이터베이스 호스팅

> 확인일: 2026-09-09
> 상태: 사용자 승인 완료
> 권장안: Supabase 서울 리전
> 예상 운영비: Pro 플랜 월 25달러부터

## 1. 결정 대상

BLOW 서버에 저장하는 계정, 이용권, 등록 기기, 관리자 설정과 감사 기록을 어디에서 운영할지 결정한다. 글, 이미지, 참고자료, OpenAI API 키와 네이버 로그인 세션은 이 서버에 저장하지 않는다.

네이버 자동 입력에 대한 서면 허락을 받기 전에는 유료 플랜을 결제하거나 운영 환경을 만들지 않는다.

## 2. 권장안

초기 5명에서 20명 규모의 MVP에는 **Supabase Pro의 서울 리전**을 권장한다.

이유:

- PostgreSQL, 인증, API와 서버 기능을 한 플랫폼에서 제공해 별도 서비스 수를 줄일 수 있다.
- 서울 리전 `ap-northeast-2`를 지정해 주 데이터 위치와 한국 사용자 지연 시간을 관리할 수 있다.
- 데이터베이스의 행 단위 권한 제어인 RLS와 인증을 연동할 수 있다.
- 관리자용 TOTP MFA를 구현할 수 있다.
- Pro 플랜은 매일 백업하며 최근 7일 백업에 접근할 수 있다.
- 월 25달러부터 시작하고 기본 지출 상한이 있어 초기 비용을 예측하기 쉽다.

## 3. 후보 비교

| 후보 | 초기 비용 | 한국 리전 | 장점 | 단점 | 판단 |
|---|---:|---|---|---|---|
| Supabase | 개발 무료, 운영 월 25달러부터 | 서울 | PostgreSQL·인증·API·MFA·RLS 통합, 7일 일일 백업 | 플랫폼 의존성, 무료 플랜 일시정지 | 권장 |
| Neon | 개발 무료, Launch 사용량 기반·일반 예시 월 15달러 | 서울 없음, 가까운 곳은 싱가포르·시드니 | 서버리스 PostgreSQL, 사용량 기반, 브랜치·복원 기능 | 별도 API·관리자 웹 배포 구성이 필요하고 운영 요소가 늘어남 | 차선 |
| Render | 개발 무료, 운영은 웹 서버·DB별 과금 | 서울 없음, 가까운 곳은 싱가포르 | 일반 Node 서버를 자유롭게 운영하기 쉬움 | 무료 DB는 30일 후 만료되고 백업이 없으며 구성 요소별 비용 발생 | 보류 |

비용은 2026-09-09 공식 가격 기준이며 환율, 세금, 초과 사용량과 가격 변경에 따라 달라진다.

## 4. 무료 플랜 사용 원칙

Supabase Free는 개발용으로만 사용한다.

- 데이터베이스 500MB와 월간 활성 사용자 5만 명 한도를 제공한다.
- 활동이 적으면 7일 뒤 프로젝트가 일시정지될 수 있다.
- 자동 백업이 제공되지 않는다.
- 실제 회원과 유료 이용권을 저장하는 운영 환경으로 사용하지 않는다.

운영 전환 시 Pro로 올리고 백업 복원 연습까지 완료해야 한다.

## 5. 운영 비용 기준

### 필수

- Supabase Pro: 월 25달러부터
- 첫 기본 Micro 프로젝트는 월 10달러 컴퓨트 크레딧으로 상쇄되는 구조
- 8GB 데이터베이스와 7일 일일 백업 포함

### 선택 또는 초과 비용

- 추가 프로젝트: 기본 크기 기준 월 10달러부터
- 커스텀 도메인: 월 10달러
- 시점 복구 기능: 월 100달러부터이며 초기 MVP에는 사용하지 않음
- 포함량을 넘는 저장 공간·네트워크 사용량

초기에는 운영 프로젝트 하나만 사용하고 기본 지출 상한을 유지한다. 개발 환경은 별도 무료 조직에 둔다.

## 6. 데이터 저장 경계

### 서버 저장 허용

- 회원 ID와 이메일
- 이용권 시작일·종료일·상태
- 등록 기기의 비가역 식별값과 변경 기록
- 등록 블로그 식별값
- 약관 동의 버전과 시각
- 앱 최소 지원 버전과 긴급 중지 상태
- 허용 OpenAI 모델 목록
- 관리자 변경 감사 기록

### 서버 저장 금지

- OpenAI API 키
- 네이버 아이디·비밀번호와 Chrome 세션
- 작성 주제, 키워드, 제목, 본문과 CTA
- 참고 URL의 추출 내용과 첨부파일
- 원본·생성 이미지
- 네이버 임시저장 글 내용

## 7. 필수 보안 설정

1. 프로젝트 지역을 “Northeast Asia (Seoul)”로 고정한다.
2. Supabase 계정과 BLOW 관리자 모두 TOTP MFA를 필수로 설정한다.
3. 외부에 노출되는 모든 테이블에서 RLS를 켜고 권한·정책을 자동 테스트한다.
4. 데스크톱 앱에는 공개용 키만 포함하고 `service_role` 비밀키는 포함하지 않는다.
5. 관리자 변경은 서버 함수에서만 수행하고 변경 전·후 값과 시각을 기록한다.
6. PostgreSQL 직접 연결은 SSL을 강제한다.
7. 운영과 개발 프로젝트를 분리하고 운영 비밀정보를 로컬 `.env`나 Git에 저장하지 않는다.
8. Pro의 일일 백업 외에 정기 논리 백업과 실제 복원 절차를 검증한다.
9. 지출 상한을 유지하고 사용량·결제 실패 알림을 켠다.
10. 대한민국 개인정보보호법 준수 여부는 별도 전문가 검토를 받는다.

## 8. 완료 기준

- H-01: 서울 리전에 개발 프로젝트가 생성된다.
- H-02: 개발·운영 환경과 비밀정보가 분리된다.
- H-03: 서버 저장 허용·금지 데이터가 스키마와 로그 검사로 강제된다.
- H-04: 익명 사용자, 일반 사용자와 관리자의 허용·거부 권한 테스트가 통과한다.
- H-05: 관리자 세션은 MFA 인증 수준을 충족해야 중요 변경을 수행할 수 있다.
- H-06: 백업에서 새 프로젝트로 복원하는 연습이 통과한다.
- H-07: 월 지출 상한과 비용 경고 경로를 운영자가 확인한다.

## 9. 승인 후 실행 순서

1. 네이버 서면 허락을 확인한다.
2. Supabase 계정을 만들고 계정 MFA를 설정한다.
3. 별도 무료 조직에 서울 리전 개발 프로젝트 하나를 만든다.
4. 데이터 분류와 최소 스키마를 확정한다.
5. RLS·권한 거부 테스트부터 작성한다.
6. 로컬 개발 연결을 검증한다.
7. 실제 베타 사용자 저장 전 Pro 운영 조직과 프로젝트를 만든다.
8. 백업·복원과 비용 알림을 확인한 뒤 베타를 시작한다.

## 10. 아직 결정하지 않는 항목

- 이메일 발송 서비스와 발신 도메인
- 사용자 로그인 방식과 비밀번호 정책의 상세값
- 관리자 웹 배포 위치
- Windows 앱 업데이트 파일 배포 위치
- 시점 복구 기능과 고가용성 옵션
