# BLOW 0.1.10 — 임시저장 완료 확인 보완

## 후속 사용자 검수

2026-09-30 배포 준비 시점에 대화의 후속 결과를 반영했습니다. 사용자는 두 글을 새로 실행해 모두 작성·임시저장됐다고 알렸고, 작업 내역과 본문·이미지·스티커 확인에도 “모두 정상이야”라고 답했습니다. 이는 사용자 PC에서 수행한 실제 네이버 검수 결과이며, 에이전트의 로컬 모의 테스트와 구분합니다. 다른 PC와 Windows 11에서의 설치·실행 검증은 아직 완료되지 않았습니다.

아래는 0.1.10을 만들 당시의 원인 분석과 검증 기록입니다. 현재 Git 및 배포 준비 상태는 [배포 준비 문서](BLOW_RELEASE_READINESS_0.1.10.md)를 참조하세요.

## 확인한 사실과 한계

- 사용자는 네이버 임시저장 목록에 이번 글이 있다고 확인했습니다. BLOW는 저장 결과 확인 단계에 남아 다음 글을 실행하지 못했습니다.
- 실제 네이버 화면과 당시 응답은 이번 작업에서 직접 관찰하지 않았습니다. 아래는 코드에서 발견하고 로컬에서 재현한 결함이며, 당시 화면의 정확한 원인을 단정하지 않습니다.
- 저장 목록 열기 기능은 저장 옆 숫자 버튼을 인식했지만, 저장 완료 확인 기능은 같은 형태를 인식하지 못했습니다.
- 기존 확인 코드는 많은 버튼을 하나씩 읽었습니다. 저장 뒤 화면이 다시 그려지면 기존 순번의 버튼을 기다릴 수 있었고, 관찰 제한 시간에도 화면을 읽는 시간이 포함되지 않았습니다.
- 이전 0.1.9 패키지 코드를 동일한 모의 화면에서 실행해 숫자가 4에서 5로 증가해도 완료 확인에 실패함을 재현했습니다. 수정 후 같은 조건에서 통과했습니다.

## 수정 내용

- ponytail 원칙에 따라 저장 목록과 완료 확인이 같은 건수 판독 함수를 사용하도록 통일했습니다. 별도 감시 시스템이나 의존성은 추가하지 않았습니다.
- 저장 옆 숫자, 접근성 이름과 화면에 보이는 숫자가 다른 버튼, 저장·임시저장 건수 표현을 함께 읽습니다. 서로 다른 숫자가 충돌하면 성공으로 단정하지 않습니다.
- 버튼과 안내 문구를 프레임별로 한 번에 읽습니다. 저장 버튼은 실제 요소를 기억해 화면 갱신 후 사라진 순번의 버튼을 기다리지 않습니다.
- 저장 직전 실제 요소가 여전히 저장 버튼인지 다시 검사합니다. 저장 버튼은 한 번만 누르고 발행 버튼은 누르지 않습니다.
- 완료 확인은 단조 증가 시계 기준 10초 동안 수행하며 화면 읽기 시간도 포함합니다. 브라우저 자체가 응답하지 않는 모든 상황에 대한 절대 시간 제한을 보장하는 것은 아닙니다.
- 새 완료 안내, 저장 건수 증가 등 실제 완료 증거가 있어야 다음 단계로 넘어갑니다. HTTP 200 응답만으로 성공 처리하거나 기존 안내를 새 성공으로 오인하지 않습니다.
- 확인 실패 시 이전·마지막 건수와 중복 재생성 금지 안내를 표시합니다.
- 기존 스티커 개선, 글 생성 조건, 임시저장만 수행하는 정책은 유지했습니다. 사용자 게시물·작업 목록·작업 내역을 직접 변경하지 않았습니다.

## 사용자 확인 순서

1. BLOW와 BLOW 전용 Chrome을 닫습니다.
2. 아래 0.1.10 설치파일로 기존 설치를 업데이트합니다. 기존 BLOW를 먼저 제거하지 마세요. 제거 시 로컬 설정·프로필이 삭제될 수 있습니다.
3. 이미 네이버에 저장된 첫 번째 글은 재생성하지 않습니다. 과거 중단 항목의 표시와 작업 내역을 소급 수정한 것은 아닙니다.
4. 자동 작성 목록에서 남은 글의 상태가 대기인지 확인합니다. 대기가 한 개라면 ‘목록 전체 자동 작성·저장 (1개)’를 눌러 남은 글만 실행합니다. 이 버튼은 대기 항목만 실행합니다.
5. 새 작업의 저장 완료 표시, 작업 내역 등록, 네이버 임시저장 목록을 확인합니다. 실제 네이버 환경에서는 이 재검증이 필요합니다.
6. 다시 멈추면 오류 전체와 저장 버튼·임시저장 건수가 보이는 화면을 캡처해 주세요. 재생성이나 저장 버튼 반복 클릭은 피합니다. 남은 새 글 작성에는 기존과 같이 AI 이용 비용이 발생합니다.
