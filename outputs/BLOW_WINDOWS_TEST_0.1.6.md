# BLOW 0.1.6 — 입력 시작 전 창 활성화 확인

## 확인한 상황과 수정 범위

- 사용자가 보낸 네이버 화면은 제목과 본문이 비어 있는 새 편집기입니다. 앞선 BLOW 오류에는 본문 입력 단계에서 창 포커스 이탈로 중단되었다고 표시되었습니다.
- 코드에는 Chrome 새 창을 연 뒤 BLOW의 `focus()`만 호출하고 활성화 완료를 확인하지 않는 경로가 있었습니다. 각 입력 단계도 시작 순간 BLOW가 활성화되어 있지 않으면 즉시 중단했습니다.
- 이번 보완은 **입력 시작 전 활성화 준비**에 한정합니다. 사용자 환경에서 창을 바꾼 주체가 Chrome인지 사용자 조작인지까지 확정한 것은 아닙니다.
- 새 글쓰기 준비 완료를 반환하기 전에 BLOW 활성화를 확인하고, 제목·본문, 이미지, 꾸미기, 임시저장 등 9개 동작 전에도 같은 확인을 적용합니다. 비활성 상태면 한 번만 활성화를 요청하고 최대 2초 안에 200ms 연속 활성 상태인지 확인합니다.
- 실제 입력 감시가 시작된 후에는 기존 blur → AbortSignal 중단 흐름을 그대로 유지합니다. 작업 도중 포커스를 반복 강탈하거나 안전 검사를 제거하지 않습니다. 닫히거나 최소화된 창, 활성화가 거절된 창은 시작할 수 없습니다.
- 앞선 **스티커 삽입 확인 오류는 미해결**입니다. 이번 빈 편집기 캡처만으로 실제 스티커 삽입 여부·확인 실패 이유는 알 수 없으며 스티커 코드를 추측으로 변경하지 않았습니다.

## 변경 파일

- `apps/desktop/src/main/automation-focus.ts` (신규): 입력 시작 전 공통 활성화 확인.
- `apps/desktop/src/main/index.ts`: 새 글쓰기 준비와 9개 입력 단계에 연결. 기존 중단 감시 보존.
- `apps/desktop/src/main/automation-focus.test.ts` (신규): 실제 IPC 핸들러와 가짜 창·세션을 이용한 지연 활성화/중단/잠금 해제 테스트.
- `apps/desktop/package.json`, `package-lock.json`: 테스트 버전 0.1.6.

ponytail 원칙에 따라 기존 감시 흐름을 재사용하고 짧은 공통 준비 함수만 추가했습니다. 새 의존성, DB 변경, 사용자 데이터 삭제는 없습니다. 이전 미커밋 수정도 유지했습니다.

## 검증 결과와 한계

- 전체 TypeScript 검사 통과.
- 전체 단위 테스트 **32개 파일, 400개 통과**. 신규 포커스/실제 IPC 경로 검사 21개 포함.
- 지연된 창 활성화 후에만 입력 시작, 활성화 실패 시 입력 금지 및 busy 잠금 해제, 감시 준비 후 창 전환 시 중단, 진행 중 입력에 AbortSignal 전달, 새 편집기 준비 시 활성화 실패를 성공으로 반환하지 않음 등을 확인했습니다.
- Windows 설치파일 빌드 및 NSIS 압축 무결성 검사 통과.
- 패키징된 메인·프리로드가 최신 빌드와 동일하고 포커스 준비 함수가 포함됨을 확인했습니다. 환경설정 비밀 파일·Chrome 프로필은 포함하지 않았습니다.
- 이번에는 가짜 창 상태·가짜 네이버 세션으로 검증했으며 실제 Windows 창 전환과 실제 네이버 글 입력·임시저장은 검증하지 않았습니다. 유료 AI 호출·게시물 변경·최종 발행도 하지 않았습니다.

## 사용자 확인 사항

1. 이전 실패 글의 제목·본문·스티커가 남아 있는 네이버 탭이 있다면 먼저 캡처해 주세요. 이번에 보낸 빈 탭과는 별개입니다. 새로고침이나 탭 닫기는 미저장 내용을 잃을 수 있습니다.
2. 필요한 미저장 내용을 확인·보존한 뒤 BLOW와 전용 Chrome을 닫고 `apps/desktop/release/BLOW-Setup-0.1.6-x64.exe`를 실행해 업데이트합니다. **기존 BLOW를 먼저 제거하지 마세요.** 제거하면 설정·프로필이 삭제될 수 있습니다.
3. 실행 중에는 BLOW를 맨 앞에 두고 다른 창을 클릭하지 마세요. 실제 입력 중 창 전환 감지는 계속 동작합니다.
4. 재생성은 기존 내용을 재사용하는 기능이 아니라 새 유료 AI 요청입니다. 스티커 오류 원인이 남아 있으므로 같은 설정의 유료 재생성을 반복하지 마세요. 기존 네이버 임시저장 목록을 확인하여 중복 글도 주의해야 합니다.
5. 내부 테스트용 미서명 파일로 Windows 보안 경고가 나타날 수 있습니다. 자동 설치와 공개 배포는 하지 않았습니다.
