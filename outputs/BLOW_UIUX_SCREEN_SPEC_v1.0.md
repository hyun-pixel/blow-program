# BLOW UI·UX 화면 및 상호작용 명세서

> 버전: 1.0
> 상태: MVP 개발 전달용
> 작성일: 2026-09-03
> 연결 문서: BLOW_PRD_v1.0.md, design-system/blow/MASTER.md
> 대상: Windows 사용자 앱, 별도 관리자 웹

## 1. 문서 목적

이 문서는 PRD의 기능을 실제 화면 단위로 바꾼 개발 기준이다. 각 화면에서 무엇을 보여주고, 사용자가 무엇을 누르며, 성공·실패·중단 상황을 어떻게 표현할지 정의한다.

우선순위가 충돌하면 다음 순서를 따른다.

1. 개인정보·자동화 안전
2. PRD의 명시적 결정
3. 이 화면 명세
4. BLOW 디자인 시스템
5. 개별 화면의 시각적 장식

## 3. 전역 내비게이션

### 왼쪽 사이드바

순서는 홈 → 새 글 작성 → 작업 내역 → 브랜드 프로필 → 연결 설정 → 도움말·고객센터로 고정한다.

- 현재 메뉴: 파란 왼쪽 표시선 + 굵은 글자 + 현재 페이지 상태
- 펼침 폭: 240px
- 접힘 폭: 72px
- 접힘 상태의 아이콘에는 툴팁과 접근 가능한 이름 제공
- 하단 계정 영역에는 회원 ID, 이용 종료일, 로그아웃 표시
- 사이드바 위에는 BLOW 워드마크와 앱 버전 표시
- 관리자 메뉴는 사용자 앱에 표시하지 않음

### 전역 상단 영역

각 화면의 주 콘텐츠 상단은 다음 순서를 따른다.

1. 화면 제목 H1
2. 한 문장 설명
3. 필요한 경우 상태 또는 보조 행동
4. 화면 본문

제목과 설명 뒤에는 32px 간격을 둔다. 페이지 전환 후 H1로 포커스를 이동해 현재 위치를 알린다.

### 앱 전체 차단 상태

다음 상황에서는 사이드바의 설정·도움말은 사용할 수 있지만 생성과 자동 입력은 차단한다.

- 이용 기간 종료
- 필수 업데이트 미설치
- 운영자가 긴급 자동 입력 중지를 켠 상태
- 서버가 세션 또는 이용권을 확인할 수 없는 상태

차단 배너에는 이유, 가능한 행동과 고객센터 경로를 함께 표시한다.

## 4. 공통 화면 상태

| 상태 | 표현 | 주요 규칙 |
|---|---|---|
| 초기 | 입력 가능한 기본 화면 | 도움말은 짧게, 고급 정보는 접음 |
| 로딩 | 버튼 너비 유지 + 스피너 + 동사형 문구 | 중복 실행 방지 |
| 성공 | 화면 내 상태 또는 토스트 | 중요한 다음 행동은 화면에 남김 |
| 입력 오류 | 상단 요약 + 필드 오류 | 첫 오류로 포커스 이동 |
| 외부 오류 | 지속형 배너 또는 중단 화면 | 사용자에게 가능한 행동만 안내 |
| 사용자 확인 필요 | 현재 단계 일시정지 | Chrome에서 해결 후 다시 확인 |
| 빈 상태 | 설명 + 행동 버튼 하나 | 장식 이미지는 선택 사항 |
| 비활성 | 낮은 강조 + 이유 문구 | 색상만 흐리게 하지 않음 |
| 이용 만료 | 생성 접근 제한 | 설정·탈퇴·고객센터는 허용 |
| 오프라인 | 서버 필요 기능 구분 | 로컬 화면의 읽기 가능 여부 표시 |

## 5. 계정과 이용권

### A-01 로그인

**목표:** 등록된 이메일과 비밀번호로 회원·이용권 상태를 확인한다.

**구성**

- BLOW 로고와 짧은 가치 문구
- 이메일
- 비밀번호 + 표시·숨김
- 로그인 버튼
- 비밀번호 찾기
- 회원가입 이동
- 앱 버전과 고객센터 링크

**상호작용**

- Enter로 로그인 가능
- 이메일 형식 오류는 API 요청 전에 표시
- 로그인 성공 후 최초 설정 미완료면 O-01, 완료면 U-01로 이동
- 다른 PC의 기존 세션이 있으면 새 로그인 성공 후 기존 세션을 종료
- IP가 같다는 이유만으로 차단하지 않음

**오류 문구**

- 계정 정보 불일치: 이메일 또는 비밀번호를 확인해 주세요.
- 이메일 미인증: 이메일 인증을 완료해 주세요.
- 이용 만료: 이용 기간이 종료되었습니다. 고객센터로 문의해 주세요.
- 서버 확인 실패: 지금은 로그인 상태를 확인할 수 없습니다. 잠시 후 다시 시도해 주세요.

### A-02 회원가입

**필드**

- 이메일
- 비밀번호
- 비밀번호 확인

비밀번호 규칙은 입력 전에 보이며 충족 여부를 글자와 아이콘으로 표시한다. 이메일 인증 전에는 로그인할 수 없다.

### A-03 이메일 인증 대기

- 인증 메일을 보낸 주소 표시
- 인증 확인 버튼
- 메일 다시 보내기
- 이메일 주소 변경
- 스팸함 확인 도움말

자동으로 계속 새로고침하지 않는다. 사용자가 인증 확인을 누르거나 제한된 간격으로만 상태를 확인한다.

### A-04 이용 기간 종료

- 제목: 이용 기간이 종료되었습니다
- 종료일
- 고객센터 문의
- 계정 설정
- 로그아웃

새 글 작성으로 이동하는 모든 경로를 차단한다. 비용과 판매 조건은 앱에서 다시 설명하지 않고 운영자가 결제 전에 별도로 안내한다.

## 6. 최초 설정 흐름

### 전체 규칙

- 총 6단계 진행 위치를 상단에 표시한다.
- 이전 단계로 돌아갈 수 있지만 필수 단계를 건너뛸 수 없다.
- 완료 전 앱을 닫으면 블로그 주소, API 키와 브랜드 입력값을 모두 삭제한다.
- 회원 계정, 이메일 인증과 이용권은 서버에 유지한다.
- 자동 저장 또는 이어서 하기 문구를 표시하지 않는다.
- 단계마다 주요 버튼은 하나만 둔다.

### O-01 약관 동의

**구성**

- 이용약관 동의 체크박스
- 개인정보처리방침 동의 체크박스
- 각 전문 보기 링크
- 모두 동의 보조 기능
- 동의하고 계속 버튼

두 항목은 각각 동의 기록을 남긴다. 모두 동의만 체크하고 개별 상태를 숨기지 않는다.

### O-02 블로그 등록

**필드**

- 네이버 블로그 주소
- 브랜드 별칭

**검사**

- 지원하는 네이버 블로그 주소 형식인지 확인
- 주소 끝의 불필요한 경로와 공백 정리
- 로그인 확인 전에는 소유 여부가 확정됐다고 표현하지 않음

**도움말**

블로그 주소는 글쓰기 화면으로 이동하는 데 사용되며 네이버 로그인 비밀번호는 BLOW에 입력하지 않습니다.

### O-03 네이버 로그인

**구성**

- 전용 Chrome 프로필을 여는 버튼
- 3단계 짧은 안내
- 현재 로그인 확인 상태
- 로그인 확인 버튼

**흐름**

1. BLOW 전용 Chrome 프로필 실행
2. 사용자가 네이버에 직접 로그인
3. 등록 블로그와 로그인된 블로그 일치 확인
4. 성공 시 다음 단계 활성화

CAPTCHA 또는 추가 인증은 사용자가 직접 완료한다. 앱은 비밀번호를 읽거나 저장하지 않는다.

### O-04 OpenAI 연결

**필드**

- API 키 입력, 기본 마스킹
- 표시·숨김 버튼
- 모델 선택
- 추론 강도 선택

**상호작용**

- API 키는 로컬 보안 저장소에만 저장
- 서버 요청·로그에 키를 포함하지 않음
- 연결 확인 성공 후 다음 단계 활성화
- 지원 모델과 지원 추론 강도만 표시
- 모델별 비교, 추천 비용 계산과 토큰 기록은 제공하지 않음

**오류 문구**

API 키를 확인하거나 고객센터로 문의해 주세요.

### O-05 브랜드 필수 정보

최초 설정에서는 필수 항목만 보여준다.

- 브랜드명
- 업종
- 핵심 서비스
- 활동 지역
- 기본 CTA
- 기본 말투

선택 항목은 최초 설정 후 U-06에서 추가한다. 글 생성에 사용할 사실만 입력하라는 설명을 제공한다.

### O-06 자동화 위험 고지

**필수 확인 내용**

- BLOW는 네이버 발행 버튼을 누르지 않음
- 네이버 화면 변경이나 인증 요청이 나타나면 안전하게 중단
- 자동 입력 이후 사용자가 직접 검토하고 발행
- 자동화 이용에 따른 네이버 서비스 정책 위험
- 비정상 종료된 미완성 작업은 복구되지 않음

체크박스 하나와 확인하고 시작 버튼을 사용한다. 긴 약관처럼 만들지 않고 핵심 문장과 자세히 보기로 나눈다.

## 7. U-01 홈

### 목적

연결 상태, 이용권과 최근 작업을 한 화면에서 확인하고 새 글 작성을 시작한다.

### 우선순위

1. 새 글 작성 버튼
2. 연결 상태
3. 브랜드와 블로그 정보
4. 최근 작업
5. 이용권·버전·고객지원

### 레이아웃

**상단 시작 영역**

- 인사 제목: 오늘도 브랜드 글을 준비해 볼까요?
- 설명
- 새 글 작성 Primary 버튼

**상태 요약 영역**

- 네이버: 연결됨 / 확인 필요
- OpenAI API: 연결됨 / 확인 필요
- 이용권: 종료일 + 남은 일수
- 등록 브랜드명과 블로그 주소

상태가 정상이면 아이콘·상태명만 간결하게 표시한다. 문제가 있는 항목은 해당 설정 화면으로 바로 이동하는 버튼을 제공한다.

**최근 작업**

- 최대 5건
- 제목
- 작성 시각
- 임시저장 완료 / 실패 / 중단
- 임시글 열기 또는 상세 보기

**하단 정보**

- 이번 달 네이버 임시저장 완료 건수
- 현재 앱 버전
- 업데이트 상태
- 고객센터

### 빈 상태

첫 작업이 없을 때 최근 작업 표를 빈 행으로 두지 않는다.

- 제목: 아직 작성한 글이 없습니다
- 설명: 브랜드 정보를 바탕으로 첫 글을 준비해 보세요.
- 버튼: 첫 글 작성

### 제외 정보

네이버 방문자 통계, 검색 유입, API 비용, 토큰 사용량과 모델 비교를 표시하지 않는다.

## 8. U-02 새 글 작성

### 목표

필수 내용과 표현 방식을 한 화면에서 설정하고 한 번의 클릭으로 생성을 시작한다.

### 데스크톱 레이아웃

- 왼쪽 65%: 주제, 키워드, 글 유형, 참고자료, CTA
- 오른쪽 35%: 모델, 추론 강도, 말투, 가독성, 이미지, 네이버 서식
- 오른쪽 설정 패널은 화면 안에서 고정되며 패널 내부를 독립적으로 스크롤하지 않는다.
- 화면 높이가 부족하면 전체 페이지가 자연스럽게 스크롤된다.
- 오른쪽 패널 접기 버튼 제공
- 화면 하단에 단일 Primary 버튼: 글 생성 시작

높은 Windows 배율이나 좁은 창에서는 오른쪽 패널을 접힌 요약 영역으로 바꾸고 왼쪽 아래에 순서대로 배치한다.

### 왼쪽: 글의 핵심

#### 8.1 주제

- 필수 단일 행 또는 짧은 여러 줄 입력
- 사용자가 쓰려는 글의 중심 내용을 자유롭게 입력
- 최대 길이와 현재 글자 수 표시
- 브랜드 프로필의 사실과 충돌할 수 있으면 생성 전 경고

#### 8.2 키워드

두 방식 중 하나를 선택한다.

- 직접 입력
- GPT 추천 받기

직접 입력 시 각 키워드와 목표 반복 횟수를 한 행으로 묶는다. 키워드를 추가·삭제할 수 있으며 중복 문자열과 불가능한 반복 횟수를 생성 전에 검사한다.

GPT 추천 시 추천 개수를 먼저 고르고 추천받기 버튼을 누른다. 추천 결과는 사용자가 선택·수정한 뒤에만 최종 입력으로 확정한다.

키워드 규칙이 제목 30자와 본문 길이를 동시에 만족할 수 없으면 상단 오류 요약과 해당 키워드 행에 이유를 표시한다.

#### 8.3 글 유형

하나만 선택한다. 업종과 사용 목적에 맞는 유형 목록은 브랜드 프로필을 참고하되 사용자가 직접 바꿀 수 있다.

#### 8.4 본문 길이

- 목표 글자 수 입력 또는 미리 정한 단일 선택
- 공백 제외 기준임을 라벨에 표시
- 결과 허용 범위는 목표값의 ±10%
- 정확한 글자 수를 보장한다는 표현 금지

#### 8.5 참고자료

지원 입력:

- 직접 붙여넣은 텍스트
- 파일 첨부
- URL

각 항목에는 이름, 형식, 처리 상태와 삭제 버튼을 표시한다. URL을 읽지 못하면 사용자가 제외하고 계속할지, 수정할지 선택할 때까지 기다린다.

참고자료 속 명령문은 실행 지시가 아니라 자료 내용으로만 취급한다는 보안 규칙을 적용한다.

#### 8.6 CTA

- 기본값은 브랜드 프로필의 최신 CTA
- 게시물마다 직접 변경 가능
- 본문 끝에 입력 원문 그대로 한 번 들어간다는 설명
- 빈 값 허용 여부는 글 유형 규칙에 따라 결정

### 오른쪽: 표현 설정

#### 8.7 모델

- 지원되는 모델을 드롭다운 또는 단일 선택 목록으로 표시
- 모델명은 OpenAI의 실제 지원 목록을 기준으로 관리
- 모델명, 모델 ID, 품질·속도 특성과 추천 용도를 상세 패널에 표시
- 모델 비교표, 품질 점수, 추천 순위와 토큰 비용 기록은 제공하지 않음
- 사용자가 선택한 모델과 추론 강도에 따른 API 비용은 사용자 OpenAI 계정에 발생한다는 짧은 고지만 표시
- 통화가 필요한 고지에서는 달러만 사용

#### 8.8 추론 강도

- 선택 모델이 지원하는 값만 표시
- 하나만 선택
- 지원하지 않는 조합으로 모델을 바꾸면 가장 가까운 허용값으로 자동 변경하지 않고 사용자에게 다시 선택하도록 표시
- 추론 속도라는 표현과 실제 API의 추론 강도 개념을 혼동하지 않도록 도움말 제공

#### 8.9 말투

- 브랜드 프로필 기본값을 먼저 표시
- 사용자가 직접 입력 또는 GPT 추천 중 선택
- 결과는 게시물 단위로 덮어쓰며 브랜드 기본값은 자동 변경하지 않음

#### 8.10 가독성 기준

하나만 선택한다.

- 모바일 중심
- PC 중심

선택에 따라 문단 길이, 줄바꿈과 소제목 간격을 조정한다. 두 옵션을 동시에 선택할 수 없다.

#### 8.11 이미지

이미지 사용 여부를 먼저 선택한다. 이미지를 사용하면 생성 이미지와 직접 첨부를 각각 켜거나 함께 사용할 수 있다. 두 출처의 이미지는 하나의 배치 그룹으로 합칠 수 있다.

**생성 이미지**

- 장수
- 비율
- 품질 모드
- 스타일
- 글 안의 배치 방식

한 게시물의 생성 이미지는 같은 비율을 사용한다.

**직접 첨부**

- 원본 파일 목록
- 업로드 순서 변경
- 표시 방식: 개별사진 / 콜라주 / 슬라이드 중 하나
- 사용자 원본은 수정하지 않으며, 네이버 한도를 맞추기 위한 사본만 필요할 때 변환·최적화한다는 안내

생성 이미지와 첨부 이미지는 순서를 섞어 하나의 그룹으로 구성할 수 있고, 그룹의 표시 방식은 개별사진 / 콜라주 / 슬라이드 중 하나를 선택한다.

#### 8.12 스티커

- 사용 / 사용 안 함
- 사용 시 개수
- 위치: 문단 전 / 문단 후 / 글 끝 등 지원 위치 중 하나 또는 정의된 반복 규칙
- 위치 미리보기는 문단 번호 중심의 간단한 구조로 제공

#### 8.13 인용구

- 사용 / 사용 안 함
- 사용 시 개수
- 위치
- 인용구 스타일 한 가지 선택

#### 8.14 구분선

- 사용 / 사용 안 함
- 사용 시 개수
- 위치
- 구분선 스타일 한 가지 선택

#### 8.15 글꼴과 정렬

- 제목 글꼴
- 소제목 글꼴
- 본문 글꼴
- 인용구 글꼴
- 글자 크기
- 정렬: 왼쪽 / 가운데 / 오른쪽 중 하나
- 강조색

네이버 편집기에서 안정적으로 적용 가능한 선택지만 제공한다. 양쪽 맞춤은 지원하지 않는다.

### 하단 요약

생성 버튼 바로 위에 다음을 한 줄 또는 두 줄로 요약한다.

- 선택 모델과 추론 강도
- 목표 글자 수 범위
- 키워드 수
- 이미지 방식과 장수
- 모바일 또는 PC 가독성

### 생성 버튼 활성화 조건

다음 조건이 모두 충족되어야 한다.

- 필수 항목 입력 완료
- API 연결 정상
- 네이버 로그인 확인
- 이용 기간 유효
- 모델·추론 조합 유효
- 글자 수와 키워드 규칙 충돌 없음
- 첨부파일과 URL 처리 결정 완료
- 필수 업데이트 완료
- 긴급 자동 입력 중지가 아님

버튼이 비활성일 때는 가장 가까운 위치에 이유를 표시한다.

### 생성 시작

1. 사용자가 글 생성 시작 선택
2. 클라이언트에서 모든 규칙 재검사
3. 오류가 있으면 API 호출 전 중단
4. 오류 요약을 보여주고 첫 오류로 이동
5. 정상이면 U-03으로 이동

- 전체 작업 중단

- 선택 즉시 확인 대화상자 없이 취소
- 팝업 또는 지속형 알림: 이미지 생성을 취소했습니다. 남은 작업은 계속 진행됩니다.
- 이미 완성된 이미지의 사용 가능 여부를 상태에 표시
- 본문 생성과 네이버 임시저장 흐름은 계속 진행
- 작업 내역에는 이미지 생성 취소 상태를 부가 정보로 기록

### 전체 작업 중단

대화상자 제목: 작업을 중단합니다

본문:

- 진행 중인 생성과 자동 입력을 중지합니다.
- 중단된 작업은 복구되지 않습니다.
- 이미 완료된 API 요청의 비용은 되돌릴 수 없습니다.

버튼:

- 계속 진행
- 작업 중단

기본 포커스는 계속 진행에 둔다. 작업 중단 후 생성된 임시 결과를 삭제하고 U-02로 돌아간다.

### 사용자 확인 필요

CAPTCHA, 본인인증 또는 네이버 로그인 만료 시:

- 현재 단계를 일시정지
- Chrome 창을 유지
- 제목: 네이버에서 직접 확인해 주세요
- 해결 방법 1–3단계
- 확인 완료 버튼
- 전체 작업 중단

사용자가 확인 완료를 누른 뒤 현재 화면을 다시 안전하게 확인한다. 예상 화면이 아니면 자동 조작하지 않는다.

### 사용자의 직접 조작 감지

자동 입력 중 사용자가 Chrome을 직접 조작하면:

- 자동 입력 즉시 일시정지
- 현재 위치를 임의로 추정하지 않음
- 계속할 수 있는지 다시 검사
- 안전하지 않으면 임시저장 여부를 직접 확인하도록 안내

### 실패

**API 관련**

API 키를 확인하거나 고객센터로 문의해 주세요.

앱은 키를 자동으로 바꾸거나 모델을 임의 변경하지 않는다. 작성 화면의 입력값은 유지하고 사용자가 문제를 해결한 뒤 직접 다시 시도한다.

**네이버 화면 변경**

현재 네이버 화면을 인식할 수 없습니다. 안전을 위해 자동 입력을 중단했습니다.

**저장 확인 실패**

임시저장 여부를 직접 확인해 주세요.

Chrome 창을 유지하고 실패를 성공으로 기록하지 않는다.

### 비정상 종료

앱 또는 PC가 꺼진 뒤 재실행하면 미완성 작업을 복구하지 않는다. 임시 결과는 삭제하고 홈에 짧은 안내만 표시한다.

브랜드 프로필에서 즉시 바꾸지 않고 U-07 연결 설정으로 이동한다. 변경 후 네이버 로그인과 블로그 일치를 다시 확인해야 한다.

## 19. 오류·중단·경계 상황

### 동시에 두 기기 로그인

- 새 기기 로그인 성공
- 기존 기기 세션 종료
- 기존 기기에는 다른 기기에서 로그인되어 세션이 종료됐다는 안내
- 공용 IP 여부는 판단 기준으로 사용하지 않음

### 이용권이 작업 중 만료

작업 시작 시 유효했다면 현재 네이버 임시저장 확인까지 마친 뒤 다음 새 작업부터 차단하는 것을 권장한다. 단, 서버 정책이 즉시 차단으로 확정되면 네이버 입력 중 데이터 손상을 막는 별도 안전 절차가 필요하다.

### API 키 변경 중 기존 작업

진행 중인 작업이 있으면 API 키 변경을 막고 현재 작업을 완료하거나 중단하게 한다.

### 블로그 변경 중 기존 작업

진행 중인 자동 입력이 있으면 블로그 주소 변경을 막는다.

### 앱 업데이트 중 작업

진행 중 작업이 없을 때만 업데이트를 설치한다. 미완성 작업 복구 기능을 만들지 않는다.

### 생성 이미지 일부 성공

- 성공한 이미지 수
- 실패 또는 취소된 이미지 수
- 성공한 이미지만 자동으로 사용하고 글 작성과 임시저장을 계속함
- 요청 장수를 충족했다고 기록하지 않고 실제 사용 수를 완료 화면과 작업 내역에 표시


### 네이버 임시저장 여부 불명확

- 성공 처리 금지
- Chrome 유지
- 직접 확인 안내
- 작업 내역은 저장 미확인 또는 실패 상태
- 사용자가 발행했는지 BLOW가 추정하지 않음

## 22. 디자인·개발 인수 조건

### 시각과 반응형

- UX-001: 1366 × 768에서 새 글 작성의 필수 입력과 생성 버튼에 접근할 수 있다.
- UX-002: 1920 × 1080에서 콘텐츠가 불필요하게 넓어지지 않는다.
- UX-003: Windows 배율 100–200%에서 텍스트·버튼·입력칸이 겹치거나 잘리지 않는다.
- UX-004: 높은 배율에서 오른쪽 패널과 사이드바를 접을 수 있다.
- UX-005: 본문 영역에 불필요한 가로 스크롤이 생기지 않는다.

### 접근성

- UX-010: 모든 핵심 기능을 키보드만으로 완료할 수 있다.
- UX-011: 포커스가 즉시 보이고 고정 영역에 완전히 가려지지 않는다.
- UX-012: 모든 의미 있는 상태가 색상 외에 아이콘과 문구로 표시된다.
- UX-013: 일반 글자 대비 4.5:1, UI 요소 대비 3:1을 충족한다.
- UX-014: 버튼과 입력은 최소 44px 높이이며 인접 조작 간격은 8px 이상이다.
- UX-015: 대화상자가 열린 동안 포커스가 내부에 머물고 닫힌 뒤 원래 위치로 돌아간다.
- UX-016: Windows 동작 줄이기 설정에서 비필수 애니메이션이 제거된다.

### 글 작성

- UX-020: 한 번에 하나만 고를 수 있는 옵션은 모두 단일 선택으로 구현된다.
- UX-021: 생성 불가 상태에는 이유가 생성 버튼 근처와 관련 필드에 표시된다.
- UX-022: 규칙 충돌은 API 요청 전에 발견된다.
- UX-023: 모델과 추론 강도는 지원 조합만 선택할 수 있다.
- UX-024: 모델 비교와 토큰 기록이 화면에 없다.
- UX-025: 이미지 생성 취소와 전체 작업 중단을 혼동하지 않는다.

### 자동 입력

- UX-030: 발행 완료로 오인할 수 있는 문구가 없다.
- UX-031: 네이버 인증 필요 시 현재 단계와 해결 행동이 분명하다.
- UX-032: 저장 확인 실패를 성공으로 표시하지 않는다.
- UX-033: 앱 비정상 종료 후 미완성 작업 복구 화면을 제공하지 않는다.

### 관리자

- UX-040: 관리자 화면에서 회원의 API 키와 콘텐츠를 볼 수 없다.
- UX-041: 이용 기간 변경 전에 변경 전·후 날짜를 확인할 수 있다.
- UX-042: 이용 기간 변경 기록은 관리자 화면에서 삭제할 수 없다.
- UX-043: 긴급 중지의 영향 범위를 저장 전에 볼 수 있다.

## 24. 고해상도 시안 제작 순서

다음 시각 설계 단계에서는 먼저 세 화면을 고해상도 프로토타입으로 만든다.

1. U-01 홈: 정보 밀도와 전체 디자인 인상 검증
2. U-02 새 글 작성: 가장 복잡한 입력·설정 구조 검증
3. U-03 작업 진행: 자동화 상태와 취소 구분 검증

세 화면을 1366 × 768 기준으로 먼저 확정하고 1920 × 1080, Windows 150%와 200% 배율 변형을 추가한다. 이 세 화면이 승인된 뒤 나머지 사용자 화면과 관리자 화면을 같은 컴포넌트로 확장한다.
