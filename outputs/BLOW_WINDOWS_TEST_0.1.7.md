# BLOW 0.1.7 — 키워드 횟수 차이는 저장 후 보고

> 사용 중지: 이후 설치 테스트에서 0.1.7에 Supabase 공개 연결값이 빠져 로그인 화면에 진입하지 못하는 문제가 확인되었습니다. 0.1.8로 업데이트하세요. 아래 기록은 당시 검증 범위이며, 가짜 계정 화면 테스트만으로 실제 패키지의 인증 설정 누락을 발견하지 못했습니다.

## 변경 내용

- 제목의 기본 키워드 횟수와 본문 키워드별 횟수가 설정과 달라도 임시저장을 진행합니다. 검사는 유지하고, 차이는 `설정 3회 / 실제 2회`와 같이 안내합니다.
- 기존 분량 안내 영역을 ‘작성 결과 안내’로 확장했습니다. 자동 작성 목록과 작업 내역의 상세 보기에서 확인할 수 있습니다.
- 보고 내용을 작업 내역 파일에 함께 보관합니다. 기존 보고 필드가 없는 이전 기록도 읽을 수 있습니다. 최대 25개 키워드와 제목·분량 안내가 있어도 작성 목록을 다시 불러올 수 있습니다.
- 글이나 키워드를 억지로 추가하지 않습니다. 모델·추론 깊이·AI 요청 지시는 변경하지 않았고, 추가 유료 재생성도 하지 않습니다.
- 로그인·블로그 불일치, 입력 실패, 이미지·꾸미기 실패, 저장 미확인 시 중단하는 기존 안전장치는 유지합니다. 제목 길이·장식 문자 및 CTA 등 다른 검사 규칙도 변경하지 않았습니다.
- 이미 실패한 글을 자동 재실행하거나 사용자 기록을 수정하지 않았습니다.

## 변경 파일

- `apps/desktop/src/main/openai-generation.ts`, `openai-generation.test.ts`: 키워드 횟수 차이를 비차단 안내로 분리하고 부족·초과·정상·제목 별도 계산 검사.
- `apps/desktop/src/main/work-history.ts`, `work-history.test.ts`: 안내 저장, 이전 기록 호환, 잘못된 입력 거부.
- `apps/desktop/src/renderer/automatic-writing.ts`, `automatic-writing.test.ts`: 완료 안내와 저장·다음 글 진행·기록 전달 검사.
- `apps/desktop/src/renderer/writing-queue.ts`: 보고 내용을 작업 내역에 전달하고 안내 개수의 저장 허용 범위 조정.
- `apps/desktop/src/renderer/WritingQueuePanel.tsx`, `WorkHistoryScreen.tsx`: 작성 결과 안내 표시.
- `apps/desktop/scripts/check-writing-recovery.mjs`: 가짜 응답으로 보고 표시·재시작 후 유지 확인.
- `apps/desktop/package.json`, `package-lock.json`: 테스트 버전 0.1.7.

ponytail 원칙으로 기존 검사·보고 경로를 재사용했고, ui-typography는 안내 문구의 표시 일관성에 적용했습니다. 새 의존성, DB 변경, 사용자 데이터 삭제는 없습니다. 이전 미커밋 변경을 유지했습니다.

## 검증

- 전체 타입 검사 통과.
- 단위 테스트 32개 파일, **415개 통과**.
- 격리된 Chrome 화면 테스트 9개, Windows Electron 화면 테스트 9개 통과. 사용자 계정 대신 가짜 계정·가짜 AI/네이버 응답을 사용했고 외부 요청을 차단했습니다.
- 실제 검사 함수로 키워드 2회/설정 3회인 글을 저장 단계까지 진행하고, 다음 글도 실행하며 글당 AI 생성은 한 번만 호출하는지 검증했습니다.
- 경고의 작업 내역 보관·다시 불러오기, 입력 실패와 저장 미확인 시 완료 처리 금지, 실패 후 입력 복구도 검증했습니다.
- 작업 내역 안내 영역의 캡처를 확인했습니다.
- 설치파일 빌드 성공. 패키지 버전과 메인·프리로드 코드가 최신 빌드와 일치함을 확인했습니다. 환경변수 파일과 Chrome 프로필은 포함하지 않았습니다.
- 압축 검사 결과 `Everything is Ok`. 실행형 설치파일의 아카이브 뒤 추가 데이터 경고는 함께 출력되었습니다.
- 실제 네이버 입력·임시저장 및 유료 AI 호출은 하지 않았습니다. 이전 스티커 삽입 확인 오류는 별도 미해결 사항입니다.

## 설치 및 확인

1. 네이버에 남은 미저장 내용이 있다면 먼저 확인·보존합니다.
2. BLOW와 전용 Chrome을 닫고 `apps/desktop/release/BLOW-Setup-0.1.7-x64.exe`를 실행하여 업데이트합니다. **기존 BLOW를 먼저 제거하지 마세요.** 제거하면 로컬 설정·프로필이 삭제될 수 있습니다.
3. 완료 후 `작업 내역 → 상세 보기 → 작성 결과 안내`에서 설정 횟수와 실제 횟수를 비교합니다. 자동 발행은 하지 않습니다.
4. 이미 실패한 항목은 자동 재실행되지 않습니다. ‘재생성’은 새 유료 AI 요청이므로 비용과 네이버 중복 글을 확인한 뒤 사용하세요.
5. 내부 테스트용 미서명 설치파일이므로 Windows 보안 경고가 나타날 수 있습니다. 자동 설치·공개 배포는 하지 않았습니다.
