## 1. 제품 요약

블로우는 브랜드 블로그를 직접 운영하는 소상공인과 사내 담당자를 위한 Windows용 네이버 블로그 작성 보조 프로그램이다. 사용자가 주제, 키워드, 브랜드 정보, 참고자료와 작성 설정을 입력하면 개인 OpenAI API를 이용해 제목·본문·이미지를 생성하고, 사용자 PC의 Chrome을 조작해 네이버 블로그 편집기에 내용을 입력한 뒤 임시저장까지만 수행한다. 사용자는 네이버 편집기에서 결과를 검토하고 직접 최종 발행한다.

### 1.1 한 문장 가치 제안

한 번의 설정으로 브랜드 글의 내용과 서식을 일관되게 만들고 네이버 임시글까지 준비하여 사용자의 반복 작성 시간을 줄인다.

### 1.2 핵심 원칙

1. 블로우는 글을 자동 발행하지 않는다.
2. 사용자 한 명당 네이버 블로그 한 개와 등록 PC 한 대만 허용한다.
3. 사용자의 OpenAI API 키, 네이버 세션, 글, 참고자료와 이미지는 블로우 서버에 저장하지 않는다.
4. 사용자는 허용된 범위 안에서 GPT 모델과 추론 강도를 직접 선택한다.
5. 프로그램은 결과를 네이버 편집기에 입력하고 사용자가 네이버에서 최종 검수한다.
6. 네이버의 추가 인증, 접근 제한 또는 예측하지 못한 화면을 우회하지 않는다.
7. UI는 부드러운 크리에이터 도구의 분위기와 고밀도 업무용 대시보드의 효율을 결합한다.

## 2. 제품 목표와 성공 정의

### 2.1 목표

- G-01: 반복적인 브랜드 블로그 글 작성 시간을 줄인다.
- G-02: 브랜드 말투, CTA, 서식과 이미지 스타일의 일관성을 높인다.
- G-03: 문의, 예약, 상담, 방문 등 사업 성과로 연결되는 글 작성을 돕는다.
- G-04: 비개발자가 복잡한 API나 자동화 기술을 이해하지 않아도 사용할 수 있게 한다.
- G-05: 사용자의 콘텐츠와 자격증명을 최소 수집 구조로 보호한다.

### 2.2 초기 운영 목표

- 협조 가능한 사용자 1명에게 무료 14일 베타 계정을 제공한다.
- 사용자 한 명이 총 3개 핵심 시나리오를 검증한다.
- 치명적 오류를 수정하고 결과를 검토한 뒤 추가 인원과 시점을 별도 승인한다.
- 초기 고객지원과 계정 관리는 운영자 한 명이 직접 수행한다.

### 2.3 성공 기준

- 비개발자 테스트 사용자가 최초 설정 후 네이버 임시글을 완성할 수 있다.
- 제목, 글자 수, 키워드 횟수, CTA 등 기계적으로 검증 가능한 작성 규칙을 충족한다.
- 지원 환경에서 생성부터 네이버 임시저장까지 핵심 시나리오가 반복 성공한다.
- 프로그램이 발행 버튼을 누르지 않는 것이 자동화 테스트로 보장된다.
- 블로우 서버에 API 키, 네이버 세션, 작성 내용 또는 이미지가 전송되지 않는다.

## 3. 대상 사용자

### 3.1 핵심 사용자

- 미용실, 뷰티, 법률, 보험 등 브랜드 블로그를 직접 운영하는 사업자
- 한 브랜드와 한 네이버 블로그를 관리하는 사내 담당자
- 글쓰기와 디자인에 익숙하지 않지만 결과를 직접 검수할 수 있는 비개발자

### 3.2 대표 사용 상황

- 서비스 소개, 정보성 글, FAQ, 사례·후기형 글, 프로모션 글 작성
- 브랜드 프로필을 재사용하며 게시물별 주제와 참고자료만 변경
- GPT가 만든 제목·본문·이미지를 네이버 초안으로 준비한 뒤 직접 수정·발행

### 3.3 MVP 비대상

- 여러 고객사 블로그를 동시에 운영하는 대행사
- 한 계정에서 여러 팀원이 협업하는 조직
- 대량 예약 발행과 자동 발행이 필요한 사용자
- macOS 또는 모바일 앱 사용자

- 전용 Chrome 프로필을 이용한 네이버 수동 로그인
- 로컬 OpenAI API 키 등록·검사·교체·삭제

- 제목·본문·이미지 생성

## 5. 정보 구조

### 5.1 사용자 프로그램 왼쪽 메뉴

1. 홈
2. 새 글 작성
3. 작업 내역
4. 브랜드 프로필
5. 연결 설정
6. 도움말·고객센터
7. 하단 계정 영역: 회원 ID, 이용권 종료일, 로그아웃

관리자 기능은 사용자 프로그램에 노출하지 않고 별도의 웹 관리자 페이지에만 제공한다.

### 5.2 홈 대시보드

- 가장 강한 시각적 우선순위: 새 글 작성
- 네이버 로그인 연결 상태
- OpenAI API 연결 상태
- 등록 블로그 주소와 브랜드명
- 이용권 종료일과 남은 일수
- 최근 작업 성공·실패 상태
- 이번 달 작성 완료 건수
- 프로그램 버전·업데이트 안내
- 고객센터 바로가기

홈에서는 네이버 방문자 통계, 검색 유입, 토큰과 비용을 표시하지 않는다.

### 5.3 새 글 작성 화면

- 화면 왼쪽 약 65%: 핵심 입력과 참고자료
- 화면 오른쪽 약 35%: 스크롤을 따라가는 설정 패널
- 자주 쓰는 설정은 항상 표시하고 고급 설정은 접을 수 있게 한다.
- 오른쪽 패널을 접으면 1366×768과 높은 Windows 배율에서도 입력 영역을 확보한다.
- 페이지 하단의 단일 주요 버튼은 글 생성 시작이다.

### 5.4 작업 내역

30일 동안 다음 정보를 로컬에 표시한다.

- 작성 일시와 글 제목
- 성공, 실패 또는 중단 상태
- 사용한 GPT 모델과 추론 강도
- 생성 및 네이버 임시저장 완료 단계
- 네이버 임시글 열기
- 같은 설정으로 새로 작성

토큰과 비용은 기록하지 않는다. 30일이 지나면 작업 내역과 본문을 자동 삭제한다.

같은 설정으로 새로 작성할 때는 글 유형, 말투, 글자 수, 가독성, 강조색, 이미지, 스티커, 인용구, 구분선, 모델과 추론 강도만 복사한다. 주제, 키워드·반복 횟수, 첨부파일과 URL은 비우며 CTA는 브랜드 프로필의 최신 기본값을 불러온다.

## 6. 전체 사용자 흐름

### 6.1 최초 설정

1. 회원가입 및 이메일 인증
2. 이용약관과 개인정보처리방침 각각 동의
3. 네이버 블로그 주소 입력
4. 사용자 PC에 설치된 Chrome의 블로우 전용 프로필 실행
5. 사용자가 네이버에 직접 로그인
6. 로그인된 블로그와 등록 URL 일치 확인
7. OpenAI API 키 입력, 표시·숨김과 연결 검사
8. 브랜드 프로필의 필수 항목 입력
9. 첫 자동 작성 전에 네이버 자동화 위험 고지 확인
10. 홈 대시보드 진입

필수 연결 단계는 건너뛸 수 없다. 최초 설정을 끝까지 완료하기 전에 프로그램이 종료되면 로컬에 입력한 블로그, API 키와 브랜드 설정을 모두 삭제하고 다음 실행 때 처음부터 다시 시작한다. 회원 계정, 이메일 인증과 결제 이용권은 서버에 유지한다.

### 6.2 일반 글 작성

1. 사용자가 주제와 기본 글 정보를 입력한다.
2. 키워드를 직접 입력하거나 GPT 추천을 받는다.
3. 브랜드 프로필의 기본값을 확인하고 게시물별 설정을 변경한다.
4. 참고 텍스트, 파일 또는 URL을 첨부한다.
5. 이미지, 서식, 모델과 추론 강도를 설정한다.
6. 프로그램이 필수값과 규칙 충돌을 검사한다.
7. 유효하면 한 번의 클릭으로 생성을 시작한다.
8. 참고자료 분석, 본문 생성, 규칙 검사와 이미지 생성을 수행한다.
9. 전용 Chrome 프로필로 네이버 편집기를 연다.
10. 제목, 본문, 이미지와 서식 요소를 입력한다.
11. 네이버 임시저장 버튼을 누른다.
12. 네이버의 저장 완료 상태를 확인한 경우에만 성공 처리한다.
13. 사용자는 네이버에서 내용을 검토하고 직접 발행한다.

### 6.3 진행 단계 표시

입력 검사 → 참고자료 분석 → 본문 생성 → 글자·키워드 검사 → 이미지 생성 → 네이버 입력 → 임시저장 확인

API 응답 시간을 정확히 예측하기 어려우므로 남은 시간이나 정확한 퍼센트는 표시하지 않는다. 현재 단계, 경과 시간과 현재 수행 중인 작업 설명을 표시한다.

## 7. 브랜드 프로필

### 7.1 필수 항목

- 브랜드명
- 업종
- 주요 서비스 또는 상품

### 7.2 선택 항목

- 지역, 가격과 영업시간
- 브랜드 소개와 핵심 강점
- 타깃 고객과 반드시 강조할 내용
- 사용 금지 표현과 필수 포함 문구
- 기본 CTA와 기본 말투
- 강조색
- 이미지 스타일
- 스티커, 인용구와 구분선의 기본 디자인
- 전화번호, 주소와 예약·상담 링크

선택 항목에는 GPT에게 추천받기를 제공한다. 입력하지 않은 사실은 GPT가 임의로 만들어내지 않고 본문에서 제외한다. 고객, 사건, 계약 등 민감한 개인정보를 입력하지 말라는 정적 안내를 표시하되 개인정보 자동 감지 기능은 제공하지 않는다.

### 7.3 정보 우선순위

브랜드 프로필과 게시물 참고자료가 충돌하면 브랜드 프로필을 우선 적용하고 충돌 내용을 결과 경고로 표시한다.

예: 브랜드 프로필 가격이 50,000원이고 첨부자료가 60,000원이면 50,000원을 사용하고 불일치 경고를 표시한다.

### 7.4 블로그 변경

회원 한 명은 네이버 블로그 한 개만 등록할 수 있다. 등록 블로그 변경은 고객센터 승인 후 처리한다.

## 8. 글 작성 입력과 생성 규칙

### 8.1 기본 입력

- 사용자가 주제 또는 작성 요청을 직접 입력한다.
- 글 유형은 사용자가 직접 선택한다.
- 권장 유형: 정보형, 서비스 소개형, 문제 해결형, 사례·후기형, 프로모션형, FAQ형, 브랜드 소개형, 지역 유입형
- 제목은 하나, 본문도 하나만 생성한다.
- 대시보드 내부에 본문 편집 미리보기를 제공하지 않는다.

### 8.2 키워드

- 기본 키워드는 최소 한 개 필수다.
- 사용자는 키워드를 직접 입력하거나 GPT 추천을 받을 수 있다.
- 보조·지역 키워드 수에는 하드 제한을 두지 않고 과도한 입력 시 경고한다.
- 각 키워드의 본문 반복 횟수를 사용자가 직접 정한다.
- 횟수는 띄어쓰기와 조사가 다른 변형을 합산하지 않고 정확히 같은 문자열만 계산한다.
- 기본 키워드는 제목에 정확히 한 번 포함한다.
- 글자 수와 키워드 횟수가 동시에 충족될 수 없으면 생성하지 않고 사용자가 값을 수정하게 한다.
- 프로그램은 키워드나 횟수를 몰래 조정하지 않는다.

### 8.3 제목

- 최대 30자이며 공백을 포함해 계산한다.
- 기본 키워드를 정확히 한 번 포함한다.
- 이모지와 장식용 특수문자를 사용하지 않는다.

### 8.4 본문 길이

- 사용자가 목표 글자 수를 입력한다.
- 공백을 제외하고 계산한다.
- 허용 오차는 목표 글자 수의 ±10%다.

### 8.5 말투

사용자는 다음 세 방식 중 하나만 선택할 수 있다.

- 미리 정의된 말투 프리셋
- 직접 설명
- 예시 글 제공

세 방식을 동시에 결합하지 않는다. 선택하지 않은 방식의 입력은 비활성화한다.

### 8.6 CTA

- 브랜드 프로필에 기본 CTA를 저장할 수 있다.
- 게시물마다 CTA를 변경할 수 있다.
- CTA는 항상 글 마지막에 배치한다.
- 사용자가 입력한 문구를 GPT가 요약, 교정 또는 변경하지 않고 정확히 사용한다.

### 8.7 출처, 해시태그와 카테고리

- 출처 표시 여부는 게시물마다 사용자가 선택한다.
- 제공되지 않은 출처를 GPT가 만들지 않는다.
- 해시태그는 사용자가 전부 직접 입력하며 GPT는 추가하거나 변경하지 않는다.
- 네이버 카테고리와 공개·발행 관련 설정은 블로우가 다루지 않는다.

### 8.8 이모지와 강조

- 본문 이모지는 게시물마다 사용 여부를 선택한다.
- 사용 시 최대 10개다.
- GPT는 굵게, 밑줄과 색상 강조 위치를 자동 선택할 수 있다.
- 강조색은 게시물당 하나만 사용자가 선택한다.

### 8.9 과장·허위 방지

- 참고자료에 없는 경력, 가격, 수치와 사례를 만들지 않는다.
- 무조건, 100%, 반드시 성공 등 결과 보장 표현을 생성하지 않는다.
- 효과와 결과는 개인 또는 상황에 따라 달라질 수 있는 형태로 작성한다.
- 사용자가 발행 전 업종별 광고 규정과 사실관계를 최종 검토한다.
- 블로우가 법적 적합성을 보증하지 않는다는 안내를 표시한다.

## 9. 참고자료

### 9.1 입력 방식

- 직접 입력한 텍스트
- 파일
- URL
- 브랜드 공용 참고자료와 게시물별 참고자료

### 9.2 지원 형식과 제한

- 문서: PDF, DOCX, TXT
- 표·가격표: XLSX, CSV
- 이미지 자료: JPG, PNG, WebP
- 파일당 최대 20MB
- 게시물당 최대 10개
- 암호화 문서는 읽지 않고 암호 해제 후 다시 첨부하도록 안내한다.
- 스캔 문서와 이미지 속 글자는 OCR로 읽고 인식 오류 가능성을 표시한다.

### 9.3 URL 처리

- 사용자가 입력한 정확한 한 페이지의 내용만 읽는다.
- 같은 사이트의 다른 페이지나 링크를 따라가지 않는다.
- 로그인 우회, robots 제한 회피 또는 접근 제한 우회를 하지 않는다.
- URL을 읽지 못하면 생성을 잠시 멈추고 URL 없이 계속 생성, URL 수정, 파일로 직접 첨부를 제공한다.
- 사용자가 결정하기 전까지 해당 페이지 내용을 추측하지 않는다.

### 9.4 추출 결과와 충돌

- 생성 전 자료에서 추출한 핵심 정보를 접을 수 있는 영역에 표시한다.
- 가격, 서비스명, 영업시간과 주소 등 핵심 사실을 보여준다.
- 사용자는 필요할 때 수정할 수 있다.
- 충돌하거나 불확실한 항목만 강하게 경고하며 매번 별도 확인을 강제하지 않는다.
- 브랜드 프로필과 충돌하면 브랜드 프로필을 우선한다.
- 브랜드 프로필에 정답이 없고 참고자료끼리 충돌하면 해당 정보만 본문에서 제외하고 나머지 글은 계속 생성한다.
- 사용자가 충돌 값을 직접 입력하면 그 값을 우선 적용한다.

### 9.5 참고자료 내부 명령 차단

첨부 문서나 웹페이지의 문장을 프로그램 명령으로 실행하지 않는다. 참고자료는 사실정보로만 취급하며 이전 지시를 무시하라는 등의 프롬프트 주입 문구를 무시한다.

## 10. 이미지 기능

### 10.1 이미지 출처와 첨부

- 사용자가 직접 첨부하거나 OpenAI 이미지 모델로 생성한다.
- 한 게시물에서 첨부 이미지와 생성 이미지를 자유롭게 혼합한다.
- JPG, PNG, WebP, HEIC 등 일반 사진 형식을 허용한다.
- 네이버에 안정적으로 입력하기 위해 필요할 때 JPG 또는 PNG로 변환한다.
- 사용자의 원본 파일은 수정하거나 삭제하지 않는다.
- 네이버 허용 한도를 넘는 이미지만 최적화한다.

### 10.2 이미지 생성

- 본문 생성과 같은 작업 흐름에서 이미지를 생성한다.
- 사용자가 생성 장수를 직접 선택한다.
- 하드 제한은 두지 않되 과도한 수량에는 처리시간 경고를 표시한다.
- 많은 수량은 배치로 처리한다.
- 게시물별로 비용 절약형 또는 고품질형을 선택한다.
- 정사각형, 세로형, 가로형 중 비율을 선택한다.
- 한 게시물의 생성 이미지는 모두 같은 비율을 사용한다.
- 이미지 안에 글자를 넣지 않는다.
- 이미지 캡션과 AI 생성 표시 문구를 자동 삽입하지 않는다.

### 10.3 이미지 스타일과 배치

- GPT 추천 스타일, 프리셋과 직접 설명을 지원한다.
- GPT가 배치 방식을 추천하고 사용자가 변경할 수 있다.
- 배치 방식은 개별사진, 콜라주와 슬라이드다.
- 생성 이미지와 첨부 이미지를 같은 배치 그룹에서 사용할 수 있다.

### 10.4 증거성 이미지 위험

사용자 결정에 따라 시술 결과, 사건 자료, 증명서처럼 사실 증거로 오인될 수 있는 이미지의 생성 자체를 일괄 차단하지 않는다. 다만 실제 사실 또는 전후 결과로 오인시키는 사용은 광고·소비자 보호·업종 규정 문제를 유발할 수 있다. 사용자는 발행 전 이미지의 사실성, 사용 권한과 표시 의무를 직접 검토해야 한다. 향후 업종별 RAG가 도입되면 해당 규정에 따라 경고 또는 차단할 수 있다.

## 11. 네이버 편집 서식

### 11.1 사진 배치

- 개별사진, 콜라주 또는 슬라이드를 사용자가 선택한다.
- GPT 추천값을 제공하되 최종 선택은 사용자에게 있다.

### 11.2 스티커

- 네이버 편집기에서 BLOW가 안전하게 식별할 수 있는 스티커 카테고리만 제공한다.
- 사용자는 스티커 카테고리 하나를 선택하고, 실제 스티커는 해당 카테고리 안에서 무작위로 선택한다.
- 선택 가능한 항목이 둘 이상이면 같은 게시물 안에서 동일한 스티커의 연속 중복을 피한다.
- 브랜드 프로필에 기본 스티커 카테고리를 저장하고 게시물마다 변경한다.
- 사용자가 콘텐츠 블록 사이의 위치와 개수를 정한다.
- 개수에 하드 제한은 두지 않고 과도한 사용만 경고한다.

### 11.3 인용구

- GPT가 기존 본문의 핵심 문장을 선택하거나 사용자가 문구를 직접 입력한다.
- 게시물당 0~3개다.
- 브랜드 기본 디자인과 게시물별 변경을 지원한다.
- 기본 위치는 GPT가 추천하며 사용자가 콘텐츠 블록 기준으로 변경한다.

### 11.4 구분선

- 개수와 위치는 사용자가 직접 지정한다.
- 하드 제한은 두지 않고 과도한 사용만 경고한다.
- 브랜드 기본 디자인과 게시물별 변경을 지원한다.

### 11.5 기본 서식

- 글꼴, 글자 크기와 글 정렬은 네이버 블로그 편집기의 사용자 기본 설정을 그대로 사용하며, BLOW는 이를 선택하거나 변경하지 않는다.
- 최초 연결 안내에서 사용자가 네이버 블로그의 기본 글꼴, 글자 크기와 글 정렬을 직접 설정하도록 안내한다.
- GPT가 글 길이와 내용에 따라 소제목 개수를 자동 결정한다.

### 11.6 가독성 기준

- 사용자가 모바일 기준 또는 PC 기준 가독성을 선택한다.
- 본문 내용은 같고 줄바꿈, 문단 길이와 이미지 간격을 선택 기준에 맞춘다.
- 최종 검토는 네이버 편집기에서 수행한다.

## 12. GPT 모델과 OpenAI 연결

### 12.1 개인 API

- 사용자 개인 OpenAI API 키를 사용한다.
- API 비용은 블로우 이용료와 별도로 사용자가 OpenAI에 부담한다.
- 판매 사이트와 결제 전 안내에서 별도 과금 사실을 고지한다.
- 프로그램 내부에는 토큰·단가·예상 비용·실제 비용을 표시하거나 저장하지 않는다.

### 12.2 API 키 관리

- API 키는 Windows 보안 저장소를 이용해 로컬 암호화한다.
- 블로우 서버로 전송하지 않는다.
- 입력값 표시·숨김, 연결 검사, 교체와 삭제 기능을 제공한다.
- API 키 오류 시 작업을 중단하고 API 키를 확인하거나 고객센터로 문의하라는 알림만 표시한다.
- 블로우가 키를 수정하거나 다른 모델로 자동 대체하지 않는다.

### 12.3 모델 선택

- 운영자가 호환성을 검증해 허용한 글쓰기 모델만 노출한다.
- 음성, 실시간 통신, 임베딩 등 글 작성과 맞지 않는 모델은 표시하지 않는다.
- 사용자는 허용 모델 안에서 모델과 추론 강도를 직접 선택한다.
- 모델명, 모델 ID, 품질·속도 특성과 추천 용도를 표시한다.
- 모델이 지원하는 추론 단계만 활성화한다.
- 기본 추론 강도는 중간이다.
- temperature, top_p, 최대 출력 토큰 같은 기술 설정은 프로그램이 자동 관리한다.
- 선택한 모델과 추론 강도를 로컬 기본값으로 저장하고 게시물마다 변경할 수 있다.

### 12.4 모델 변경과 오류

- 관리자는 허용 모델, 설명, 추천 용도, 지원 종료 여부와 기본 추천값을 변경할 수 있다.
- 서버에는 사용자 API 키나 콘텐츠를 저장하지 않는다.
- 저장된 모델이 종료되거나 허용 목록에서 제외되면 자동 대체하지 않는다.
- 사용자가 새 모델과 추론 강도를 직접 선택하기 전에는 생성을 시작하지 않는다.
- API 키, 잔액 또는 사용 한도 문제는 간단한 한국어 알림 후 중단한다.
- 사용자가 문제를 해결한 뒤 직접 다시 시도하며 자동 반복 재시도하지 않는다.
- 작성 폼의 입력값은 유지한다.

### 12.5 OpenAI 전송 고지

블로우 서버에 콘텐츠를 저장하지 않더라도 글 생성에 필요한 입력, 참고자료와 요청 내용은 사용자의 API 요청으로 OpenAI에 전송된다. 사용자는 고객, 사건, 계약 등 민감정보를 입력하지 않아야 한다. OpenAI의 데이터 처리 정책은 변경될 수 있으므로 판매 및 개인정보 안내에서 최신 공식 정책을 연결한다.

## 13. Chrome과 네이버 자동 입력

### 13.1 실행 환경

- Windows에 설치된 사용자 Chrome을 사용한다.
- 블로우 전용 Chrome 프로필을 별도로 만든다.
- 사용자는 전용 프로필에서 네이버에 한 번 직접 로그인한다.
- 블로우는 네이버 ID와 비밀번호를 입력받거나 서버에 저장하지 않는다.
- MVP 초기 지원 범위는 최신 정식 Chrome이다.
- 직전 정식 버전은 출시 또는 초기 사용자 확대 전에 별도 회귀 검증을 통과한 뒤 지원 범위에 추가한다.

### 13.2 자동화 범위

1. 등록 블로그 경로 열기
2. 글쓰기 화면 진입
3. 제목과 본문 입력
4. 이미지와 서식 요소 입력
5. 네이버 임시저장 버튼 클릭
6. 저장 완료 상태 확인

프로그램 코드에는 발행 버튼 클릭 동작을 구현하지 않는다.

### 13.3 저장 확인과 중단

- 버튼을 클릭했다는 사실만으로 성공 처리하지 않는다.
- 네이버 화면의 저장 완료 문구 또는 상태 변화를 확인한 경우에만 성공으로 기록한다.
- 확인하지 못하면 Chrome을 그대로 열어두고 저장 여부를 직접 확인하라고 표시한다.
- 로그인, CAPTCHA와 본인인증 화면이 나타나면 자동화를 중단한다.
- 사용자가 직접 인증한 뒤 이어서 입력을 눌러야 재개한다.
- 인증을 우회하거나 대신 입력하지 않는다.
- 자동 입력 중 사용자의 마우스 또는 키보드 조작을 감지하면 즉시 일시정지한다.
- 예상한 화면 요소를 찾지 못하면 임의의 위치를 클릭하지 않고 안전 중단한다.

### 13.4 정책 출시 관문

네이버 브라우저 자동화는 서비스 정책상 높은 위험을 가진다. 유료 출시 전 네이버 정책과 전문 법률 검토를 완료하고 가능하면 네이버의 서면 허용 범위를 확인한다. 허용 범위가 불명확하면 상용 자동 입력 기능의 출시 여부를 다시 판단한다. 사용자가 최종 발행을 직접 하더라도 자동 입력 행위 자체의 정책 위험이 사라지지 않는다.

## 14. 취소, 실패와 재생성

### 14.1 진행 중 취소

- 항상 전체 작업 중단을 표시한다.
- 이미지 생성 중에는 이미지만 취소하고 계속을 추가 표시한다.
- 전체 중단은 복구되지 않으므로 확인 팝업을 표시한다.
- 이미지 취소는 이미지 생성이 취소되었다는 알림만 표시하고 글 작성과 네이버 입력을 계속한다.
- 취소 전에 완성된 이미지는 사용할 수 있다.
- 이미 완료된 API 요청은 되돌릴 수 없음을 안내한다.

### 14.2 일부 실패와 비정상 종료

- 이미지 일부만 실패하면 성공한 이미지만 사용하고 전체 작업을 계속한다.
- 진행 중 프로그램이나 PC가 꺼지면 작업을 복구하지 않는다.
- 다음 실행 시 이전 작업이 비정상 종료되었으니 네이버 임시글을 확인하라고 한 번 표시한다.
- 로컬의 미완성 글과 임시 생성 이미지는 자동 삭제한다.
- 네이버에 남은 글은 프로그램이 임의로 삭제하지 않는다.

### 14.3 재생성

- 제목만, 본문만, 선택 이미지만 또는 전체를 다시 생성할 수 있다.
- 본문 재생성 시 키워드 횟수, 글자 수 조건과 CTA 원문을 유지한다.
- 새 결과가 완성되기 전에는 기존 네이버 초안을 덮어쓰지 않는다.
- 새 결과가 완성된 뒤 사용자가 기존 초안에 교체 적용을 확인해야 수정한다.
- 재생성은 새로운 API 요청임을 안내하되 비용이나 토큰 수는 표시하지 않는다.

## 22. 권장 기술 구조 [제안]

이 절은 사용자 확정 결정이 아니라 구현 위험과 MVP 속도를 고려한 기술 권장안이다. 개발 착수 전 기술검증이 필요하다.

### 22.1 데스크톱 앱

- Electron + React + TypeScript, Windows 10·11 x64 패키지
- Chrome 제어: Playwright의 Chrome 채널과 영구 컨텍스트를 이용한 전용 프로필 실행 후보
- 설치된 최신 정식 Chrome 호환성은 POC에서 확인했으며, 직전 정식 버전은 출시 또는 초기 사용자 확대 전에 별도 기술검증 필수
- 로컬 데이터: SQLite 또는 동등한 로컬 데이터베이스
- 자격증명: Windows DPAPI 또는 OS 보안 저장소
- 설치: 정식 외부 배포 전 Microsoft Artifact Signing의 공개 신뢰(Public Trust) Windows 코드 서명을 적용한 설치 패키지

선정 이유: UI 구현 생태계가 크고 Chrome 자동화 도구와 통합하기 쉬워 초기 MVP 위험이 상대적으로 낮다. 단, 설치 용량과 메모리 사용량이 커질 수 있으므로 성능 검수가 필요하다. Playwright 공식 문서는 자사 번들 Chromium에서 가장 안정적이며 다른 브라우저 버전은 동작이 보장되지 않는다고 안내하므로, 사용자 설치 Chrome 방식은 반드시 별도 기술검증을 통과해야 한다.

### 22.2 서버와 관리자 웹

- 인증·이용권·관리자 API와 최소 공개 설정만 제공
- PostgreSQL 계열 관계형 데이터베이스
- 비밀번호는 직접 저장하지 않고 검증된 인증 서비스 또는 강한 해시 사용
- TLS 통신과 서버 비밀정보 환경변수 관리
- 관리자 MFA와 감사 로그
- 사용자 콘텐츠 업로드 API는 만들지 않음
- Electron 화면은 contextIsolation과 프로세스 sandbox를 켜고 nodeIntegration을 끔
- 제한적인 Content Security Policy 적용과 모든 IPC 발신자 검증
- 권한이 있는 Electron 화면에서 외부 웹 콘텐츠를 직접 실행하지 않음
- 관리자 웹은 React 또는 Next.js 기반 별도 앱
- 일반 사용자 API와 관리자 API 권한 분리

### 22.3 자동화 안전 설계

- 네이버 화면의 예상 요소와 상태를 확인한 뒤에만 다음 동작 수행
- 의미가 불확실한 좌표 기반 무작위 클릭 금지
- 각 단계에 고유 작업 ID와 상태 기록
- 발행 버튼 선택자와 발행 동작 자체를 코드에서 제외
- 네이버 편집기 변경을 조기에 찾는 자동 호환성 테스트 구축

- 탈퇴·제거 후 로컬 자료 삭제
- 진단 자료 전송 전 민감정보 제거

### 26.4 UI·접근성 테스트

- 키보드 전체 이동과 포커스 복귀
- 100~200% Windows 배율
- 1366×768과 1920×1080
- 색 대비와 오류의 비색상 표현
- 동작 줄이기 설정
- 비개발자 1명 최초 설정 관찰 테스트

### 26.5 1명 베타

- 개발 과정에 참여하지 않은 비개발자 한 명을 우선하며 가능하면 Windows 11 x64 사용자를 선정한다.
- 사용자가 기본 글, 이미지·서식, 안전 중단·복구 시나리오를 한 번씩 수행한다.
- 운영자가 비밀번호를 입력하거나 대신 조작하지 않은 상태에서 최초 설정을 관찰한다.
- 스크린샷과 진단 자료는 사용자가 확인하고 직접 보낼 때만 수집한다.
- 총 3개 시나리오 모두 확인된 임시저장까지 완료되고 치명적 오류가 0건일 때 통과한다.
- Windows 10·11 호환성은 한 명의 베타 결과에 의존하지 않고 별도 실제 PC 회귀 테스트로 검증한다.
- 자동 최종 발행, 잘못된 블로그 입력, 인증정보 서버 전송이 한 번이라도 발생하면 즉시 중단한다.

## 28. 2차 광고 규정 RAG 방향

이 기능은 MVP에 포함하지 않고 별도 기획과 법률 검토 후 진행한다.

- 의료, 법률, 보험 등 업종별 공식 규정 문서 분리
- 출처, 시행일, 버전과 갱신일 필수 기록
- 법률 전문가 검토를 통과한 자료만 활성화
- 코드에 규칙을 고정하거나 모델을 재학습시키지 않고 별도 검색 지식베이스로 관리
- 글 작성 때 해당 업종과 문장에 관련된 조항만 검색해 전달
- 오래된 규정 자동 비활성화
- 명확한 금지 규정은 생성 차단과 근거 표시
- 해석이 필요한 항목은 경고 후 사용자 최종 판단
- RAG가 법률 자문이나 광고 적합성 보증을 제공하지 않는다는 고지

## 29. 개발 권장 순서

1. 네이버 정책·상용화 가능성 검토와 자동 입력 기술검증
2. 계정·이용권·기기 제한과 관리자 기본 기능
3. 로컬 데이터 구조, API 키와 Chrome 전용 프로필
4. 브랜드 프로필과 새 글 작성 폼
5. GPT 제목·본문 생성과 규칙 검증
6. 이미지 생성·첨부와 서식 모델
7. 네이버 편집기 입력과 임시저장 확인
8. 취소·오류·중단과 긴급 중지
9. 설치·업데이트·탈퇴·제거 흐름
10. 접근성·호환성·보안 테스트
11. 협조 사용자 1명 선행 배포
12. 결과 검토 후 추가 베타 인원과 시점 별도 승인

네이버 편집기 자동 입력의 제한된 기술검증은 2026-09-09에 조건부 통과했다. 네이버 자동화 관련 외부 문의·자문은 사용자 측에서 완료했으며 이 PRD에서는 같은 검토를 반복하지 않는다. 세부 자문 자료는 사용자 측에서 보관하고 이후 개발은 사용자가 확정한 허용 범위와 운영 기준을 전제로 진행한다.

## 32. 최종 MVP 정의

블로우 MVP는 Windows 10 22H2 x64 또는 Windows 11 x64 환경에서 한 사용자가 개인 OpenAI API와 한 개의 네이버 블로그를 연결하고, 한 번에 한 게시물의 제목·본문·이미지·서식을 생성하여 네이버 임시글로 저장한 뒤 직접 검수·발행하는 유료 데스크톱 서비스다.

MVP의 가치는 자동 발행이나 대량 생산이 아니라 다음 세 가지로 제한한다.

1. 브랜드 글 작성 시간을 줄인다.
2. 반복되는 글쓰기·이미지·서식 작업을 일관되게 만든다.
3. 최종 통제권과 발행 책임을 사용자에게 남긴다.
