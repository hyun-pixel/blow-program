# BLOW 디자인 시스템

> 버전: 1.0
> 상태: MVP 개발 기준
> 기준 문서: outputs/BLOW_PRD_v1.0.md
> 적용 범위: Windows 사용자 앱, 관리자 웹 대시보드

특정 화면에 design-system/blow/pages/[화면명].md가 있으면 해당 파일의 규칙이 이 문서를 보완한다. 접근성 기준과 충돌하는 시각적 선택은 적용하지 않는다.

## 1. 제품 디자인 정의

BLOW는 미용실, 법률, 보험, 뷰티 등 브랜드 블로그 실무자가 글 작성부터 네이버 임시저장까지 진행하는 고밀도 업무 도구다. 감성적인 콘텐츠 제작 도구의 부드러움과 전문 업무 프로그램의 명확성을 함께 갖는다.

### 핵심 원칙

1. **다음 행동이 분명해야 한다.** 각 화면에는 가장 중요한 주요 행동을 하나만 강조한다.
2. **한 화면에서 많이 확인하되 복잡해 보이지 않아야 한다.** 관련 정보는 묶고, 고급 설정은 접을 수 있게 한다.
3. **자동화 상태를 숨기지 않는다.** 현재 작업, 사용자 개입 필요 여부와 실패 원인을 쉬운 문장으로 표시한다.
4. **안전한 중단을 우선한다.** 네이버 화면을 확실히 인식하지 못하면 임의 조작하지 않는다.
5. **전문가용이지만 설명은 쉽게 쓴다.** API, 모델, 추론 강도 같은 전문 용어에는 짧은 도움말을 제공한다.
6. **장식보다 콘텐츠와 상태가 우선이다.** 강한 그라데이션, 과도한 그림자와 불필요한 카드 중첩을 사용하지 않는다.

### 시각적 성격

- 밝은 회청색 바탕과 흰색 작업 영역
- 신뢰감을 주는 짙은 파란색 주요 행동
- 선명한 정보 위계와 촘촘하지만 답답하지 않은 간격
- 일관된 Lucide 계열 선형 SVG 아이콘
- 라이트 모드만 지원
- 제품 화면에는 입장 애니메이션이나 스크롤 연출을 사용하지 않음

## 3. 타이포그래피

### 글꼴

- 기본: SUIT Variable
- 대체: SUIT, Pretendard, Noto Sans KR, Segoe UI, sans-serif
- 앱 설치 파일에 글꼴을 포함해 외부 폰트 서버에 의존하지 않는다.
- 사용 굵기: 400, 500, 600, 700
- 숫자 표와 날짜에는 tabular-nums lining-nums를 적용한다.

### 크기 체계

| 토큰 | 크기 / 줄높이 / 굵기 | 사용 |
|---|---|---|
| --type-page-title | 1.5rem / 1.25 / 700 | 화면당 하나의 H1 |
| --type-section-title | 1.125rem / 1.35 / 700 | 주요 영역 H2 |
| --type-card-title | 1rem / 1.4 / 600 | 카드·대화상자 제목 |
| --type-body | 0.9375rem / 1.6 / 400 | 기본 UI 본문 |
| --type-body-strong | 0.9375rem / 1.6 / 600 | 값과 핵심 문구 |
| --type-label | 0.875rem / 1.45 / 600 | 입력 라벨, 버튼 |
| --type-helper | 0.8125rem / 1.5 / 400 | 도움말, 메타 정보 |

기본 브라우저 글자 크기 16px 기준으로 각각 24px, 18px, 16px, 15px, 14px, 13px에 해당한다. 사용자가 글자를 확대하면 rem 기준으로 함께 커져야 한다.

### 문장과 배치 규칙

- 한 화면의 제목 계층은 H1–H3 세 단계 안에서 끝낸다.
- 본문은 기본 왼쪽 정렬이며, 중앙 정렬은 한 줄짜리 빈 화면 제목에만 제한한다.
- 긴 설명의 한 줄 길이는 최대 65자 안팎으로 제한한다.
- 제목 바로 다음에 설명 문단이 오면 32px 간격을 둔다.
- 입력 라벨과 입력칸은 8px, 입력 그룹 사이는 24px를 기본으로 한다.
- UI에서 밑줄은 본문 안의 실제 링크에만 사용한다. 메뉴와 버튼에는 사용하지 않는다.
- 말줄임표는 …, 범위는 en dash –를 사용한다.
- 전문 UI 문구에 이모지와 연속 느낌표를 사용하지 않는다.

## 4. 간격·크기·형태

### 4px 간격 체계

| 토큰 | 값 | 사용 |
|---|---:|---|
| --space-1 | 4px | 아이콘 군집 내부 |
| --space-2 | 8px | 아이콘–라벨, 라벨–입력 |
| --space-3 | 12px | 좁은 행 내부 |
| --space-4 | 16px | 기본 형제 간격 |
| --space-5 | 20px | 조밀한 카드 패딩 |
| --space-6 | 24px | 기본 카드 패딩, 입력 그룹 간격 |
| --space-8 | 32px | 영역 내부 구분, 제목–설명 |
| --space-12 | 48px | 주요 영역 간격 |
| --space-16 | 64px | 큰 화면의 페이지 여백 상한 |

한 구성 안에서 최소 세 단계의 간격을 사용해 관계를 드러낸다. 컨테이너 바깥 패딩은 내부 항목 사이 간격보다 크게 한다.

### 크기

- 기본 버튼·입력 높이: 44px
- 큰 주요 버튼 높이: 48px
- 아이콘 버튼 실제 클릭 영역: 최소 44 × 44px
- 인접 조작 요소 사이: 최소 8px
- 기본 아이콘: 18 × 18px
- 강조 아이콘: 20 × 20px
- 사이드바 펼침: 240px
- 사이드바 접힘: 72px
- 오른쪽 설정 패널: 360–400px
- 대화상자: 440–520px, 화면 너비보다 작게 유동 처리

### 모서리와 그림자

| 토큰 | 값 | 사용 |
|---|---:|---|
| --radius-control | 8px | 버튼, 입력, 배지 |
| --radius-card | 12px | 카드, 패널 |
| --radius-dialog | 16px | 대화상자 |
| --shadow-popover | 0 8px 24px rgba(15,23,42,.12) | 메뉴·팝오버 |
| --shadow-dialog | 0 20px 48px rgba(15,23,42,.20) | 대화상자 |

일반 카드에는 그림자를 사용하지 않고 배경 차이와 얇은 구분선으로 영역을 구분한다. 클릭 가능한 카드만 호버 시 테두리를 진하게 한다.

## 5. 레이아웃

### 앱 셸

- 최상위: 제목 표시줄 + 사이드바 + 주 콘텐츠
- 사이드바 메뉴 순서: 홈, 새 글 작성, 작업 내역, 브랜드 프로필, 연결 설정, 도움말·고객센터
- 하단 계정 영역: 회원 ID, 이용 종료일, 로그아웃
- 관리자 기능은 사용자 앱에 노출하지 않는다.

### 화면 폭과 Windows 배율 대응

| 유효 콘텐츠 폭 | 동작 |
|---|---|
| 1280px 이상 | 사이드바 240px, 작성 화면 65:35 두 열 |
| 960–1279px | 사이드바 접기 제공, 설정 패널 360px 유지 |
| 720–959px | 사이드바 72px 아이콘형, 오른쪽 설정 패널 접기 기본값 |
| 719px 이하 | 한 열 재배치, 메뉴는 드로어, 주요 버튼은 화면 하단 고정 가능 |

실제 검수 기준은 1366 × 768과 1920 × 1080, Windows 배율 100%, 125%, 150%, 200%다. 확대 시 정보를 숨기지 않고 재배치한다. 표처럼 이차원 구조가 필요한 경우에만 해당 영역 내부 가로 스크롤을 허용한다.

## 6. 공통 컴포넌트

### 6.1 버튼

| 종류 | 용도 | 시각 |
|---|---|---|
| Primary | 화면의 단일 핵심 행동 | Primary 700 배경 + 흰색 라벨 |
| Secondary | 취소가 아닌 보조 행동 | 흰색 배경 + Primary 700 테두리·라벨 |
| Tertiary | 낮은 우선순위 행동 | 투명 배경 + Text Primary 라벨 |
| Destructive | 탈퇴, 전체 작업 중단 | Error 배경 + 흰색 라벨 |
| Icon | 접기, 닫기, 도움말 | 44px 클릭 영역 + 접근 가능한 이름 |

- 한 영역에 Primary는 하나만 둔다.
- 호버는 150ms 색상 전환만 사용한다. 위치 이동과 확대 효과는 사용하지 않는다.
- 누름 상태는 호버보다 한 단계 진한 색상으로 표시한다.
- 포커스는 즉시 나타나는 이중 외곽선으로 표시한다: 안쪽 흰색 간격 + 바깥쪽 Focus 3px.
- 로딩 버튼은 너비를 유지하고 스피너와 처리 중… 문구를 함께 표시한다.
- 비활성 버튼은 이유를 인접 도움말이나 오류 요약으로 설명한다.

### 6.2 입력 필드

- 라벨은 항상 입력칸 위에 표시하고 필수 또는 선택을 글자로 구분한다.
- 플레이스홀더는 예시이며 라벨을 대신하지 않는다.
- 기본 경계는 Control Border, 호버는 Text Primary, 포커스는 Primary 600 + 외곽선이다.
- 오류는 Error 경계 + 오류 아이콘 + 필드 바로 아래 문장을 함께 사용한다.
- 오류 요약을 화면 상단에 제공하고 첫 번째 오류로 포커스를 이동한다.
- 비밀번호와 API 키는 기본 마스킹하며 표시 버튼과 접근 가능한 상태명을 제공한다.

### 6.3 단일 선택과 다중 선택

- 한 항목만 가능한 옵션은 라디오 그룹이나 단일 선택 카드로 구현한다.
- 여러 항목 선택이 허용될 때만 체크박스를 사용한다.
- 선택 상태는 배경색 외에도 체크 아이콘, 테두리와 선택됨 상태를 제공한다.
- 모델과 추론 강도는 각각 하나만 선택한다.

### 6.4 카드와 상태 행

- 단순 정보는 카드로 남발하지 않고 제목–값 행 또는 구분된 섹션으로 표현한다.
- 카드 전체가 클릭 가능할 때만 포인터와 호버 테두리를 사용한다.
- 성공·실패·대기·중단 상태는 색상 + 아이콘 + 상태명으로 표시한다.
- 날짜, 남은 일수와 작업 건수는 숫자 폭이 고정되도록 표시한다.

### 6.5 알림

- 일반 성공: 우측 하단 토스트, 4–6초 후 닫힘, 수동 닫기 제공
- 입력 오류: 화면 상단 오류 요약 + 해당 필드 인라인 오류
- 계속 진행되는 주의: 화면 안의 지속형 알림 배너
- 결정이 필요한 상황: 대화상자
- Windows 알림: 앱이 비활성 상태일 때만 PRD에 정의된 중요 사건에 사용

토스트만으로 복구에 필요한 정보를 전달하지 않는다.

### 6.6 대화상자

- 전체 작업 중단, 탈퇴, 추가 인증처럼 결정을 요구할 때만 사용한다.
- 제목은 결과를 질문형이 아닌 명확한 문장으로 쓴다.
- 기본 포커스는 안전한 행동에 둔다.
- Esc로 닫을 수 있어야 하며 닫힌 뒤 원래 버튼으로 포커스를 돌린다.
- 키보드 포커스는 대화상자 안에 가둔다.
- 파괴적 버튼은 주요 안전 버튼과 16px 이상 떨어뜨린다.

### 6.7 단계 진행 표시

- 순서: 입력 검사 → 참고자료 분석 → 본문 생성 → 글자·키워드 검사 → 이미지 생성 → 네이버 입력 → 임시저장 확인
- 완료, 현재, 대기, 실패, 사용자 확인 필요 상태를 아이콘과 문구로 구분한다.
- 정확한 퍼센트와 남은 시간은 표시하지 않는다.
- 현재 단계, 경과 시간과 현재 수행 중인 작업 설명은 표시한다.
- 이미지 생성 취소는 전체 중단과 시각적으로 분리한다.

### 6.8 표와 목록

- 헤더 아래 한 줄 구분선만 기본으로 사용하며 모든 셀에 테두리를 두르지 않는다.
- 숫자는 오른쪽 정렬하고 문자 정보는 왼쪽 정렬한다.
- 행 행동은 마지막 열에 두고 아이콘만 사용할 경우 툴팁과 접근 가능한 이름을 제공한다.
- 좁은 화면에서는 중요 열을 유지한 카드형 목록으로 전환한다.

## 7. 움직임과 피드백

- 색상·배경·테두리 전환: 150–200ms, ease-out
- 메뉴·팝오버: 120–180ms, 작은 투명도 변화만 사용
- 대화상자: 180–220ms, 투명도와 4–8px 이내의 이동만 허용
- 포커스 표시: 0ms
- 작업 단계 변화는 즉시 문구를 갱신하고 aria-live=polite로 알린다.
- prefers-reduced-motion: reduce 또는 Windows 동작 줄이기 설정에서는 비필수 전환을 제거한다.
- 무한 반복 애니메이션, 반짝임과 자동 재생 캐러셀을 사용하지 않는다.

## 8. 아이콘

- Lucide SVG 한 세트를 기본으로 사용한다.
- 메뉴 20px, 필드·버튼 18px, 상태 16–18px를 기본으로 한다.
- 의미가 있는 아이콘은 3:1 이상의 대비와 접근 가능한 이름을 갖는다.
- 라벨과 함께 쓰는 장식 아이콘은 보조기기에서 숨긴다.
- 이모지, 채워진 아이콘과 선형 아이콘의 혼용을 금지한다.

## 9. UI 문구

- 사용자 행동으로 시작한다: API 키 확인하기, 브랜드 프로필 저장.
- 버튼은 2–8자의 동사형을 우선한다.
- 오류는 문제 + 다음 행동 순서로 쓴다: API 키를 확인하거나 고객센터로 문의해 주세요.
- 기술적 내부 오류 코드, 스택 추적과 토큰 사용량을 사용자에게 표시하지 않는다.
- 사용자가 직접 해결할 수 없는 일을 해결하라고 요구하지 않는다.
- 발행 완료로 오인될 수 있는 게시 완료 대신 네이버 임시저장 완료를 사용한다.

## 10. 접근성 기준

- 일반 글자 대비 4.5:1 이상, 큰 글자 3:1 이상
- 입력 경계, 아이콘, 선택·오류·포커스 표시 3:1 이상
- 모든 핵심 기능은 Tab, Shift+Tab, Enter, Space와 Esc로 조작 가능
- 포커스 외곽선 최소 2px, 권장 3px, 컴포넌트와 2px 이상 분리
- 포커스가 고정 헤더·패널·툴팁에 완전히 가려지지 않음
- 모든 클릭 영역 44 × 44px 이상, 인접 조작 간격 8px 이상
- 색상만으로 상태를 전달하지 않음
- 200% 글자 확대와 Windows 배율에서 잘림·겹침 없이 재배치
- 한 화면에 H1 하나, 제목 단계 생략 금지
- 실제 버튼은 button, 이동은 링크를 사용
- 반복 사이드바를 건너뛸 수 있는 본문으로 건너뛰기 링크 제공
- 툴팁은 호버와 키보드 포커스 모두에서 열리고 Esc로 닫힘

## 11. 금지 패턴

- 한 화면에 동등하게 강한 주요 버튼 여러 개
- 모든 내용을 카드에 넣어 테두리와 그림자를 겹치는 구성
- 텍스트 없는 색상 상태, 아이콘만 있는 오류
- 자리표시자만 있는 입력칸
- 호버해야만 알 수 있는 필수 정보
- 비활성 버튼만 보여주고 이유를 설명하지 않는 상태
- 정확하지 않은 진행률과 남은 시간
- 위치가 움직이거나 확대되는 호버 효과
- 제품 화면의 강한 그라데이션, 유리 효과, 장식용 3D 그래픽
- API 비용·토큰 사용량·모델 비교 기능
- 네이버 발행 버튼처럼 오해될 수 있는 앱 내부 행동

## 12. 개발 전·후 검수

### 개발 전

- 모든 화면이 하나의 주요 행동을 가지는지 확인
- 단일 선택과 다중 선택이 데이터 규칙과 일치하는지 확인
- 빈 상태, 로딩, 성공, 실패, 중단, 만료 상태가 정의됐는지 확인
- 실제 전경·배경 색상 대비를 계산

### 개발 후

- 1366 × 768, 1920 × 1080에서 확인
- Windows 배율 100%, 125%, 150%, 200%에서 확인
- 키보드만으로 최초 설정과 글 작성 완료
- Chrome 최신·직전 정식 버전에서 자동 입력 확인
- 동작 줄이기 설정에서 비필수 애니메이션 제거 확인
- 화면 읽기 프로그램에서 라벨, 오류와 진행 단계 읽기 확인
- 긴 브랜드명, 긴 제목, 200% 글자 확대에서 잘림 확인

## 14. 결정 기록

- 자동 추천의 분홍·청록 팔레트와 Inter는 기존 PRD 및 한글 실무 도구의 성격과 충돌해 채택하지 않았다.
- 자동 추천에서 확인된 평면적 구성, 적은 효과, 높은 정보 밀도와 짧은 상태 전환은 채택했다.
- PRD의 #CBD5E1 테두리는 조작 요소 경계 대비가 부족해 장식용으로 제한하고 #64748B를 조작 요소 경계로 추가했다.
- 제품의 핵심 사용 환경이 Windows 데스크톱이므로 SUIT를 앱에 포함하고 외부 폰트 요청을 피한다.
