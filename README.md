# BLOW

BLOW는 브랜드 블로그 실무자가 글과 이미지를 준비하고, 전용 Chrome에서 네이버 블로그 임시저장까지 진행하는 Windows 데스크톱 프로그램입니다.

## 현재 배포 준비 상태

현재 데스크톱 버전은 **0.1.10**입니다. 사용자가 두 글 연속 작성·네이버 임시저장·작업 내역을 정상 확인했습니다. 설치파일은 아직 미서명이므로 일반 고객용 공개 다운로드는 준비되지 않았습니다.

- [0.1.10 배포 준비 및 홈페이지 연결 안내](outputs/BLOW_RELEASE_READINESS_0.1.10.md)
- [0.1.10 저장 확인 검증 기록](outputs/BLOW_WINDOWS_TEST_0.1.10.md)

아래 POC 절차는 초기 기술검증 기록입니다. 현재 자동 작성·로컬 보관·설치 검증 상태는 위 문서를 우선 확인합니다.

## 네이버 연결 POC

1. 네이버 블로그 주소 형식 검사
2. BLOW 전용 Chrome 프로필 실행
3. 사용자의 수동 네이버 로그인 대기
4. 로그인된 블로그와 입력 주소 비교
5. 확인된 글쓰기 링크 클릭
6. 글쓰기 화면 진입 확인

입력한 블로그 주소는 앱 종료 후 저장하지 않습니다.

## 네이버 제목·본문 입력 POC

1. 글쓰기 화면 주소 재확인
2. 제목과 본문 입력 영역을 각각 한 개로 식별
3. 기존 내용이 없는 빈 새 글인지 확인
4. 제목과 본문을 문단 단위로 입력
5. 편집기 결과와 원문 비교

이 단계는 구현과 자동 테스트를 마쳤으며 실제 네이버 편집기 반복 검증을 진행합니다. 입력값은 디스크에 저장하지 않으며, 사용자가 임시저장을 선택하면 네이버의 저장 버튼을 한 번 조작합니다. 최종 발행은 실행하지 않습니다.

## 로컬 편집기 POC

1. BLOW 전용 Chrome 프로필 실행
2. 제목과 본문 입력
3. 입력 결과 재확인
4. 임시저장 실행 및 상태 확인

가짜 편집기에는 최종 발행 기능이 없습니다.

## 개발 명령

데스크톱 앱을 빌드하기 전에 `apps/desktop/.env.example`을 참고해 해당 작업 폴더의 `apps/desktop/.env.local`에 `VITE_SUPABASE_URL`과 `VITE_SUPABASE_PUBLISHABLE_KEY`를 설정합니다. Git worktree를 새로 만들면 이 로컬 파일은 자동 복사되지 않습니다.

배포용 앱에는 `sb_publishable_` 공개 키만 사용합니다. 비밀 키·`service_role` 키는 넣지 않습니다. 연결값이 없거나 비공개 키이면 빌드가 중단됩니다. 환경 파일은 Git 및 설치파일에 포함하지 않고, 필요한 공개 연결값만 빌드 결과에 포함합니다.

```powershell
npm install
npm run test
npm run build
npm run dev
```

Chrome이 설치된 개발 PC에서는 다음 명령으로 각 자동화 경계를 확인할 수 있습니다.

```powershell
npm run poc:mock
npm run poc:naver:public
```

`poc:naver:public`은 새 임시 Chrome 프로필로 네이버 공개 화면만 열고, 비로그인 상태를 안전하게 감지한 뒤 임시 프로필을 삭제합니다.

POC 실행 중 생성되는 Chrome 프로필과 로컬 데이터는 Git에 포함되지 않습니다. API 키, 네이버 아이디·비밀번호, 글과 이미지를 코드나 로그에 기록하지 않습니다.
